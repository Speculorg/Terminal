# core/fsm

FSM — реализация детерминированного жизненного цикла сервиса.

## Инварианты TERM-1
- FSM создаётся в `BaseService.build_fsm()` и НЕ входит в `Deps`.
- Порядок состояний фиксирован (изменение — только через ADR).
- Для каждого состояния исполняется фиксированный список политик.
- Semantics:
  - OK  -> продолжать
  - RETRY -> повторять текущее состояние (до дедлайна или бесконечно, если дедлайн=0)
  - FAIL -> ERROR

## Управление
- `pause/resume/restart/stop`

## Дедлайны
Берутся через `cfg.get(...)` для совместимости с `configs.env`.
`0` означает “дедлайн отключён”.

## DaemonRunner
Внутри `core/fsm/daemon/runner.py` — управление процессом демона (start/stop/restart/signal).
Он не проверяет readiness демона — это задача политик (NetPolicy/HTTP checks).
