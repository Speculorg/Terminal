
# Интеграции Speculorg.Terminal (MVP)

**Система интеграций Speculorg.Terminal** обеспечивает надёжное и стандартизированное взаимодействие с внешними источниками данных и операций. Это ключевой компонент платформы, который поддерживает подключение к различным `ExternalService` (Внешним сервисам), таким как биржи, агрегаторы данных, криптовалютные кошельки, аналитические платформы и сигнальные сервисы.

Этот документ описывает архитектуру системы интеграций, её цели, принципы и основные элементы.

---

## Введение

Система интеграций создана для упрощения и стандартизации взаимодействия с внешними API. Она предоставляет унифицированный интерфейс, устраняя сложности работы с разнородными и часто несовместимыми API Внешних сервисов.

- **Цели системы интеграций:**
    - Обеспечение единого подхода к подключению и управлению интеграциями.
    - Снижение сложности взаимодействия с различными API.
    - Расширение возможностей через подключение к новым Внешним Сервисам.
    - Возможность быстрого добавления новых Внешних сервисов без нарушения существующей архитектуры.
    - Обеспечение устойчивой работы интеграций через обработку ошибок, управление лимитами запросов и централизованный мониторинг.
    - Обеспечение масштабируемости и возможности работы с большим количеством запросов и высокими нагрузками.
    - Улучшение безопасности, контроля доступа к интеграциям и шифрования данных.

- **Ключевые особенности:**
    - Система интеграций определена в Контексте `Speculorg.Terminal.Integration` и реализована через Компонент `Speculorg.Terminal.Integration.Service`.
    - Основной элемент системы — `ExternalServiceAdapter` (Адаптер Внешнего сервиса), который абстрагирует сложность работы с API Внешних сервисов и предоставляет надёжный механизм для обмена данными.
    - Использует модульную архитектуру, что позволяет гибко расширять функциональность Адаптеров через подключаемые Модули.

---

## Принципы

- **Стандартизация:** Все Адаптеры наследуются от базового класса `BaseAdapter`, который определяет унифицированный интерфейс и абстрактные методы для взаимодействия с API внешнего сервиса.
- **Независимость:** Каждый Адаптер изолирован и развернут как самостоятельный FastAPI-микросервис.
- **Модульность:** Расширение функциональности Адаптера осуществляется через подключаемые модули.
- **Гибкость:** Интеграции поддерживают расширение и настройку без необходимости модификации существующего кода.
- **Масштабируемость:** Адаптеры можно масштабировать горизонтально для обработки больших объёмов данных.
- **Изоляция ответственности:** Каждый Адаптер решает чётко определённый набор задач, имеет изолированное хранилище данных и состояния, минимизируя зависимости.
- **Надёжность:** Реализация политики обработки ошибок, повторов и ограничения частоты запросов (rate limiting).
- **Производительность:** Использование асинхронных процессов для обработки данных.
- **Безопасность:** Управление секретами и конфиденциальными данными через HashiCorp Vault, шифрование данных при передаче (TLS) и контроль доступа.
- **Интеграция с API:** внешних сервисов осуществляется через RESTful и WebSocket.

## Компоненты

Компоненты интеграции Speculorg.Terminal — это ключевые модули системы, отвечающие за взаимодействие с внешними источниками данных и операций. Их главная цель — обеспечить надёжное, стандартизированное и масштабируемое соединение с `ExternalService` (Внешними сервисами), такими как биржи, агрегаторы данных, кошельки и сигнальные платформы.

### Структура

- `ExternalService`: Абстракция Внешнего сервиса для представления его данных и операций в системе Speculorg.Terminal.
- `ExternalServiceAdapter`: Независимые микросервисы, предоставляющие интерфейс для работы с одним конкретным Внешним сервисом.
- `Module`: Программные библиотеки, расширяющие функциональность адаптеров.
- `Speculorg.Terminal.Integration.Service`: Компонент для управления системой интеграций, потоками данных и запросами между Адаптером и системой.
- `Speculorg.Terminal.Management.Service`: Основной управляющий компонент, управление жизненным циклом Адаптеров и их Модулей.
- `Speculorg.Terminal.Infrastructure.Service`: Компонент для доступа и управления сквозной функциональностью.
- `Speculorg.Terminal.Security.Service`: Компонент для управления секретами, шифрования данных и контроля доступа.

## Внешний сервис

### Описание

Экземпляр `ExternalService` (далее — Внешний сервис) представляет собой абстракцию, которая консолидирует данные и операции, связанные с конкретной внешней системой, такой как биржа, агрегатор данных, кошелёк или сигнал. Эта абстракция служит для унификации работы с внешними системами в программной среде Speculorg.Terminal, предоставляя централизованное представление API, данных и операций.

Внешний сервис взаимодействует с системой через `ExternalServiceAdapter` (далее — Адаптеров), который реализует техническую интеграцию с API этой внешней системы. Внешний сервис содержит `ExternalServiceSection` (далее — Секции), которые разделяют функциональность этой внешней системы на логические области, такие как `Spot`, `Futures`, `Metrics` и другие.

### Атрибуты

- **Основные:**
    - `uuid`: Уникальный идентификатор Внешнего сервиса.
    - `version`: Версия Внешнего сервиса (например, `1.0.0`).
    - `name`: Название Внешнего сервиса (например, `MEXC`, `CoinMarketCap`).
    - `type`: Тип Внешнего сервиса.
    - `status`: Текущий статус Внешнего сервиса (`active`, `maintenance`, `deprecated`).
    - `sections`: Список Секций ExternalServiceSection.
    - `metadata`: Дополнительные параметры в формате JSON.
    - `adapter`: Адаптер, который взаимодействует с API этого Внешнего сервиса.
    - `website_url`: Адрес веб-сайта.
    - `documentation_url`: Ссылка на документацию API Внешнего сервиса.

- **Мониторинг и логирование:**
    - `metrics` (JSON): Сводка метрик производительности.
    - `logs` (JSON): Лог операций и событий.

- **Временные метки:**
    - `created_at` (datetime): Дата и время добавления Внешнего сервиса в систему.
    - `updated_at` (datetime): Дата последнего обновления конфигурации.
    - `last_checked_at` (datetime): Дата последней проверки состояния.

### Функции

- **Базовые операции:**
    - Регистрация и конфигурирование этого Внешнего сервиса в системе.
    - Управление связями между Внешним сервисом и его Адаптером.
    - Управление Секциями, определяющими функциональные области Внешнего сервиса.
    - Мониторинг состояния Внешнего сервиса, его Секций и связанного Адаптера.
    - Обновление параметров и конфигурации этого Внешнего сервиса.

- **Типовые операции:**
    - `fetch_sections()`: Получение списка всех Секций, связанных с Внешним сервисом.
    - `fetch_adapters()`: Получение списка всех Адаптеров, связанных с Внешним сервисом.
    - `configure_rate_limits()`: Настройка лимитов запросов для API Внешнего сервиса.
    - `update_api_metadata()`: Обновление технической информации об API (например, версии, доступных методах).
    - `monitor_sections()`: Проверка состояния Секций и их активности.
    - `monitor_adapters()`: Мониторинг состояния и производительности Адаптеров, связанных с Внешним сервисом.

- **Поддержка Секций и Адаптеров:**
    - Интеграция новых Адаптеров для обеспечения поддержки API и расширения возможностей Внешнего сервиса.
    - Динамическое подключение и управление Секциями Внешнего сервиса.
    - Обновление связей между Секциями и Адаптерами для оптимизации обработки данных.

### Связи

- **Внутренние связи:**
    - `ExternalServiceAdapter`: Адаптеры, которые обрабатывают запросы и операции для данного Внешнего сервиса.
    - `ExternalServiceSection`: Секции, разделяющие функциональность Внешнего сервиса на логические области (например, Spot, Futures, Metrics).
    - `Entities`: Сущности, управляемые в рамках Внешнего сервиса.
    - `Events`: События, генерируемые в процессе работы с данным Внешним сервисом.
       - Примеры: изменения статусов, уведомления о лимитах, ошибки API.

- **Внешние связи:**
    - `Speculorg.Terminal`: Пользователи и внутренние процессы платформы, использующие данные и операции Внешнего сервиса через его интерфейсы.
    - `APIs`: Интерфейсы, предоставляемые для взаимодействия с системой.
       - Примеры: REST API и WebSocket.
    - `Speculorg.Terminal.Management.Service`: Управление жизненным циклом Внешнего сервиса, включая его регистрацию, обновление и мониторинг.
    - `Speculorg.Terminal.Infrastructure.Service`: Предоставление сквозной функциональности, такой как логирование, мониторинг и конфигурирование.
    - `Speculorg.Terminal.Integration.Service`: Управление интеграциями, обменом данными и запросами, связанными с данным Внешним сервисом.
    - `Speculorg.Terminal.Security.Service`: Управление доступом и безопасностью.

## Типы Внешних сервисов

### Описание

**ExternalServiceType** (тип Внешнего сервиса) представляет собой абстракцию, которая описывает функциональность и возможности конкретного типа Внешнего сервиса, такого как биржа, агрегатор данных, кошелёк или источник сигналов. Новые типы Внешних сервисов добавляются в систему через расширение Контекста `Speculorg.Terminal.Integration` с помощью соответствующих Секций и Модулей.

Каждый новый тип Внешнего сервиса расширяет функциональность системы, добавляя поддержку специфичных операций и данных через специализированные Адаптеры.

Для управления разными типами Внешних сервисов используются Модули:

- `Speculorg.Terminal.Integration.Exchange.Module`: Поддержка бирж.
- `Speculorg.Terminal.Integration.Aggregator.Module`: Поддержка агрегаторов данных.
- `Speculorg.Terminal.Integration.Wallet.Module`: Поддержка криптовалютных кошельков.
- `Speculorg.Terminal.Integration.Signal.Module`: Поддержка платформ сигналов.

### Поддерживаемые типы

- **Exchange**
    - **Системное имя:** Speculorg.Terminal.Integration.ExternalServiceTypes.Exchange
    - **Цель:** Интеграция с биржами.
    - **Функции:**
        - Получение служебных данных.
        - Получение рыночных данных.
        - Получение торговых данных.
        - Выполнение торговых операций.
    - **Модуль:**
        - `Speculorg.Terminal.Integration.Exchange.Module`
    - **Примеры Адаптеров:**
        - `Speculorg.Terminal.Integration.Exchange.MEXC.Adapter`
        - `Speculorg.Terminal.Integration.Exchange.KuCoin.Adapter`

- **Aggregator**
    - **Системное имя:** Speculorg.Terminal.Integration.ExternalServiceTypes.Aggregator
    - **Цель:** Интеграция с агрегаторами данных.
    - **Функции:**
        - Получение служебных данных.
        - Получение данных об активах и рынках.
        - Получение глобальных рыночных данных.
        - Получение исторических рыночных данных.
        - Обогащение аналитики с помощью глобальных метрик.
        - Аналитика on-chain данных.
    - **Модуль:**
        - `Speculorg.Terminal.Integration.Aggregator.Module`
    - **Примеры адаптеров:**
        - `Speculorg.Terminal.Integration.Aggregator.CoinMarketCap.Adapter`
        - `Speculorg.Terminal.Integration.Aggregator.CoinGecko.Adapter`
        - `Speculorg.Terminal.Integration.Aggregator.Glassnode.Adapter`

- **Wallet**
    - **Системное имя:** Speculorg.Terminal.Integration.ExternalServiceTypes.Wallet
    - **Цель:** Интеграция с кошельками.
    - **Функции:**
        - Получение служебных данных.
        - Получение балансов и истории.
        - Отправка транзакций.
        - Поддержка Multi-Sig для крупных транзакций.
    - **Модуль:**
        - `Speculorg.Terminal.Integration.Wallet.Module`
    - **Примеры адаптеров:**
        - `Speculorg.Terminal.Integration.Wallet.TrustWallet.Adapter`
        - `Speculorg.Terminal.Integration.Wallet.Ledger.Adapter`

- **Signal**
    - **Системное имя:** Speculorg.Terminal.Integration.ExternalServiceTypes.Signal
    - **Цель:** Интеграция с источниками сигналов.
    - **Функции:**
        - Получение служебных данных.
        - Получение настроений и выявления трендов.
    - **Модуль:**
        - `Speculorg.Terminal.Integration.Signal.Module`
    - **Примеры Адаптеров:**
        - `Speculorg.Terminal.Integration.Signal.Twitter.Adapter`

---

### Добавление новых типов

Так как система интеграций определена в Контексте `Speculorg.Terminal.Integration` и реализована через Компонент `Speculorg.Terminal.Integration.Service`, добавление новых типов Внешних сервисов происходит следующим образом:

- **Создание Секции:** Определяется Секция для Контекста `Speculorg.Terminal.Integration` с набором операций и данных нового типа Внешнего сервиса.
- **Создание Модуля:** Создаётся и подключается новый Модуль для `Speculorg.Terminal.Integration.Service`, который реализует функциональность для этой новой Секции.
- **Создание Адаптеров:** Создаются и подключаются новые Адаптеры для Внешних Сервисов, относящихся к этому типу.

## Адаптер интеграции

### Описание

Экземпляр `ExternalServiceAdapter` (далее — Адаптер) представляет собой независимый микросервис, отвечающий за интеграцию платформы Speculorg.Terminal с конкретным `ExternalService` (далее — Внешним сервисом). Каждый Адаптер взаимодействует с одним Внешним сервисом, обеспечивая унифицированный интерфейс для работы с его API.

Основная задача Адаптера — абстрагировать сложность взаимодействия с внешними API, предоставляя платформе стандартизированные инструменты для работы с данными и операциями.

Функциональность Адаптера расширяется за счёт подключения `Module` (далее — Модулей), которые добавляют поддержку отдельных `ExternalServiceSection` (далее — Секций), таких как Spot, Futures, Metrics и другие.

Адаптер состоит из следующих элементов:

- Базовая логика управления жизненным циклом.
- Базовая логика взаимодействия с API Внешнего сервиса.
- Базовая логика управления потоками данных и запросов.
- Базовая логика представления данных в системе.
- Подключаемые Модули, которые содержат функциональность отдельной Секции и расширяют базовую логику Адаптера.
- Сквозная функциональность для выполнения инфраструктурных задач системы.

### Атрибуты

- **Основные:**
    - `uuid` (UUID): Уникальный идентификатор Адаптера.
    - `name` (string): Название Адаптера (например, `MEXC.Adapter`, `CoinMarketCap.Adapter`).
    - `external_service_id` (UUID): Идентификатор Внешнего сервиса, связанного с Адаптером.
    - `host` (string): URL или IP-адрес хоста, на котором развёрнут Адаптер.
    - `api_endpoint` (string): Основной URL для взаимодействия с API Внешнего сервиса.
    - `api_version` (string): Текущая версия API, используемая Адаптером.
    - `status` (enum): Текущий статус Адаптера (`active`, `inactive`, `error`, `maintenance`).

- **Конфигурационные:**
    - `modules` (array): Список подключённых Модулей.
    - `rate_limit` (integer): Максимальное количество запросов в минуту.
    - `retry_policy` (JSON): Политика обработки ошибок и повторов запросов.
    - `dependencies` (array): Список зависимостей, необходимых для работы Адаптера.
    - `auth_method` (enum): Метод аутентификации для API (`api_key`, `oauth2`, `none`).

- **Мониторинг и логирование:**
    - `metrics` (JSON): Сводка метрик производительности.
    - `logs` (JSON): Лог операций и событий.

- **Временные метки:**
    - `created_at` (datetime): Дата и время создания Адаптера.
    - `updated_at` (datetime): Дата последнего обновления конфигурации.
    - `last_checked_at` (datetime): Дата последней проверки состояния.

### Функции

- **Базовые операции:**
    - Регистрация и конфигурирование.
    - Подключение к API Внешнего сервиса.
    - Мониторинг состояния и производительности.
    - Обновление конфигурации.

- **Типовые операции:**
    - `fetch_data()`: Получение данных из API.
    - `send_request()`: Отправка данных в API.
    - `execute_operation()`: Выполнение операций.
    - `monitor_status()`: Проверка доступности API и состояния Адаптера.

- **Поддержка модулей:**
    - Динамическое подключение Модулей, обеспечивающих поддержку Секций.

### Связи

- **Внутренние связи:**
    - `ExternalService`: Внешний сервис, с которым связан Адаптер.
    - `ExternalServiceSection`: Секции, доступные для Внешнего сервиса этого Адаптера.
    - `Module`: Модули, реализующие функциональность доступных Секций.
    - `Entities`: Сущности используемые в рамках этого Адаптера.
    - `Events`: События, порождаемые этим Адаптером.

- **Внешние связи:**
    - `Speculorg.Terminal`: Пользователь и процессы использующие функциональность данного Адаптера.
    - `APIs`: Интерфейсы, предоставляемые для других систем или модулей.
    - `Speculorg.Terminal.Management.Service`: Управление жизненным циклом.
    - `Speculorg.Terminal.Infrastructure.Service`: Мониторинг, логирование и конфигурация.
    - `Speculorg.Terminal.Integration.Service`: Управления интеграциями, потоками данных и запросами.
    - `Speculorg.Terminal.Security.Service`: Управление доступом и безопасностью.

## Управление интеграциями

Система управления интеграциями Speculorg.Terminal организована на основе распределённого подхода, где управление жизненным циклом Адаптеров, потоками данных, безопасностью и инфраструктурной поддержкой делегировано различным компонентам системы. 

Распределение обязанностей между компонентами:

- `Speculorg.Terminal.Integration.Service`: Управление системой интеграций, потоками данных и запросами между Адаптерами и системой.
- `Speculorg.Terminal.Management.Service`: Управление жизненным циклом Адаптеров и их Модулей.
- `Speculorg.Terminal.Infrastructure.Service`: Обеспечение сквозной функциональности (логирование, мониторинг, конфигурация).
- `Speculorg.Terminal.Security.Service`: Управление секретами, безопасностью передачи данных и контроль доступа.

### Функции управления

- **Регистрация адаптеров:**
    - Регистрация новых Адаптеров через `Speculorg.Terminal.Management.Service`.
    - Обнаружение Адаптеров через Consul и настройка параметров.

- **Мониторинг состояния:**
    - Проверка доступности Адаптеров через `Speculorg.Terminal.Management.Service`.
    - Сбор данных о производительности через `Speculorg.Terminal.Infrastructure.Service`.

- **Управление конфигурацией:**
    - Изменение параметров через `Speculorg.Terminal.Management.Service`.
    - Хранение конфигураций и метаданных в `Speculorg.Terminal.Infrastructure.Service`.

- **Безопасность:**
    - Управление API-ключами и секретами через `Speculorg.Terminal.Security.Service`.
    - TLS-шифрование для защиты данных при передаче.

### Потоки данных

- **Потоки запросов:**
    - Обработка входящих запросов через REST API и WebSocket.
    - Управление запросами через `Speculorg.Terminal.Integration.Service`.

- **Обработка данных:**
    - Данные от внешних сервисов передаются через RabbitMQ для асинхронной обработки.

### API

- **REST API**
    - `GET /integration/status`: Проверка состояния всех Адаптеров.
    - `POST /integration/adapters`: Добавление нового Адаптера.
    - `PUT /integration/adapters/{adapter_id}`: Обновление параметров Адаптера.
    - `DELETE /integration/adapters/{adapter_id}`: Удаление Адаптера.

- **WebSocket API**
    - `WS /integration/notifications`: Получение уведомлений о состоянии Адаптеров в реальном времени.
