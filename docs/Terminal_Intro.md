
# Обзор Speculorg.Terminal

**Speculorg.Terminal** — это исследовательский проект многофункциональной платформы для автоматизации торговли, анализа данных и управления рисками на финансовых рынках.

- **Текущий статус проекта:** *Разработка MVP (Минимально Жизнеспособного Продукта).*

## Возможности

Основные возможности Speculorg.Terminal (MVP):

- **Инфраструктура, интеграции и управление**
    - Готовая среда в контейнере (Python, Docker, GitHub, Ansible, Kubernetes).
    - Базы данных: PostgreSQL, TimescaleDB.
    - Система безопасности и управления пользователями (Keycloak, OAuth2, RBAC).
    - Система логирования и мониторинга (Prometheus, Grafana, ELK Stack, Sentry, OpenTelemetry).
    - Система конфигураций и секретов (Consul, Vault).
    - Кэширование (Redis).
    - Очереди сообщений и задач (RabbitMQ, Celery).
    - Базовый административный интерфейс.
    - Подключение к API агрегатора данных **CoinMarketCap**.
    - Подключение к API бирж **MEXC**, **KuCoin** (спотовые рынки).

- **Сбор рыночных данных**
    - Получение доступных рынков, активов и торговых пар.
    - Получение тикеров, стаканов, ленты сделок, OHLCV.
    - Получение глобальных рыночных рейтингов и метрик.
    - Единое API для работы с рыночными данными.

- **Сбор торговых данных**
    - Подключение к API бирж для получения данных о балансах, ордерах, сделках.
    - Единое API для работы с торговыми данными.

- **Управление активами**
    - Реестр активов.
    - Разные категории активов (криптовалюты, фиатные валюты, акции, облигации и т.д.).
    - Избранные активы (**FavoriteAssets**).
    - Перспективные активы (**WatchlistAssets**).
    - Критерии мониторинга WatchlistAssets (**MonitoringCriteriaAssets**).
    - Единое API для работы с реестром активов.

- **Управление торговлей**
    - Базовые торговые операции на спотовых рынках (лимитные и рыночные ордера).
    - Отслеживание сделок и исполнение ордеров.
    - Ведение позиций и мониторинг статуса ордеров в реальном времени.
    - Формирование отчётов по балансу, позициям, истории сделок и ордеров.
    - Единое API для работы с торговой функциональностью.

- **Управление рисками**
    - Базовые механизмы управления рисками.
    - Единое API для управления рисками.

- **Анализ данных**
    - Базовые механизмы анализа данных.
    - Единое API для работы с аналитикой.

- **Хранение данных:**
    - Хранение исторических рыночных данных.
    - Хранение исторических торговых данных.
    - Единое API для работы с историческими данными.

## Архитектура

Архитектура Speculorg.Terminal основана на предметных **Контекстах** (**DDD**), каждый из которых отвечает за отдельную бизнес-область и реализуется в виде микросервиса.

Часть сервисов и бизнес-логики строятся на Django, а интеграционные адаптеры, API-шлюз и часть сервисов на FastAPI. Это обеспечивает независимость и возможность раздельного масштабирования компонентов. Компонентам можно расширять функциональность через подключение модулей **Module (Модуль)**.

Подробнее: [Архитектура Speculorg.Terminal](Terminal_Architecture.md)

### Контексты

Каждый **Контекст** выполняет строго определённую задачу в рамках одной предметной области и формирует программные интерфейсы, абстракции, сущности и структуры, необходимые для оперативной работы с данными, процессами и функциями этой области.

- **Основные контексты:**
    - `Speculorg.Terminal.Market` - работа с рыночными данными.
    - `Speculorg.Terminal.Trading` - работа с торговыми данными и операциями.
    - `Speculorg.Terminal.Assets` - работа с активами.
    - `Speculorg.Terminal.Analytics` - работа с анализом данных.
    - `Speculorg.Terminal.RiskManagement` - контроль стратегий и ограничений.
    - `Speculorg.Terminal.API` - API-шлюз и маршрутизатор запросов.
    - `Speculorg.Terminal.Security` - безопасность.
    - `Speculorg.Terminal.Management` - административное управление системой.
    - `Speculorg.Terminal.Integration` - интеграции с внешними сервисами.
    - `Speculorg.Terminal.Infrastructure` - инфраструктура (аутентификация, логирование, конфигурация , мониторинг, очереди сообщений) и сквозная функциональность.
    - `Speculorg.Terminal.Notifications` - уведомления.

**ContextSection (Секция Контекста)** это логическая часть **Контекста**, представляющая собой набор функций и данных для выполнения группы специфичных подзадач. **Секции** разделяют бизнес-логику на группы в пределах **Контекста** и предоставляют возможность модульного расширения функциональности.

### Компоненты

**Компоненты** в системе Speculorg.Terminal представляют собой независимые единицы, которые выполняют задачи конкретного **Контекста**, интегрируют конкретный **Внешний сервис** или расширяют возможности другого **Компонента**.

Типы компонентов разделяются на **ContextMicroservice (Микросервис Контекста)**, **ExternalServiceAdapter (Адаптер Внешнего сервиса)** и **Module (Модуль)** и могут быть реализованы в виде **микросервиса** или программной **библиотеки**.

- **ContextMicroservice:**
    - `Speculorg.Terminal.API.Service` - реализация API-шлюза и маршрутизатора.
    - `Speculorg.Terminal.Security.Service` - реализация контекста безопасности.
    - `Speculorg.Terminal.Management.Service` - реализация контекста управления.
    - `Speculorg.Terminal.Integration.Service` - реализация системы управления интеграциями.
    - `Speculorg.Terminal.Infrastructure.Service` - реализация системы вспомогательных сервисов и управления имя.
    - `Speculorg.Terminal.Assets.Service` - реализация системы активов, портфелей и балансов.
    - `Speculorg.Terminal.Trading.Service` - реализация системы работы с торговыми данными и операциями.
    - `Speculorg.Terminal.Market.Service` - реализация системы работы с рыночными данными.
    - `Speculorg.Terminal.Analytics.Service` - реализация системы аналитики.
    - `Speculorg.Terminal.RiskManagement.Service` - реализация системы рисков и защитных механизмов.
    - `Speculorg.Terminal.Notifications.Service` - реализация системы уведомлений.

- **ExternalServiceAdapter:**
    - `Speculorg.Terminal.Integration.Exchanges.MEXC.Adapter`
    - `Speculorg.Terminal.Integration.Exchanges.KuCoin.Adapter`
    - `Speculorg.Terminal.Integration.Aggregators.CoinMarketCap.Adapter`

- **Module:**
    - `Speculorg.Terminal.Integration.Exchanges.KuCoin.Spot.Module`
    - `Speculorg.Terminal.Integration.Exchanges.MEXC.Spot.Module`
    - `Speculorg.Terminal.Integration.Exchanges.MEXC.Futures.Module`
    - `Speculorg.Terminal.Integration.Aggregators.CoinMarketCap.Global.Module`
    - `Speculorg.Terminal.Integration.Aggregators.CoinMarketCap.Metrics.Module`
    - и ещё масса инфраструктурных и сервисных модулей.

За регистрацию и **управление жизненным циклом** всех **Компонентов** системы отвечает `Speculorg.Terminal.Management.Service`.

Все Компоненты интегрированы в единую систему **сквозной функциональности** через `Speculorg.Terminal.Infrastructure.Service`.

### Интеграции

Один из ключевых аспектов Speculorg.Terminal — интеграция с различными источниками данных и торговыми платформами. Для этого выделен отдельный контекст `Speculorg.Terminal.Integration`, который определяет абстракции и логику взаимодействия с внешними сервисами различных типов: биржами, агрегаторами данных, сигнальными платформами и кошельками. Он предоставляет унифицированные интерфейсы, устраняя сложности работы с разнородными и часто несовместимыми API внешних сервисов.

Этот контекст реализован в компоненте `Speculorg.Terminal.Integration.Service`, который управляет потоками запросов и данных через множество подключаемых **ExternalServiceAdapter**.

Интеграции реализуются через адаптеры **ExternalServiceAdapter**, которые являются отдельными микросервисами, абстрагируют сложность работы с API внешних сервисов и предоставляют надёжный механизм обмена данными.

**ExternalServiceAdapter** использует модульную архитектуру, что позволяет гибко расширять его функциональность за счёт подключаемых модулей.

- **Первоначальный список интеграций**:  
    - ExternalServiceAdapter для биржи **MEXC** + Spot.Module.
    - ExternalServiceAdapter для биржи **KuCoin** + Spot.Module.
    - ExternalServiceAdapter для агрегатора **CoinMarketCap** + Assets.Module + Metrics.Module.

## Инфраструктура

Speculorg.Terminal развертывается в облачном или локальном окружении.

Так как проект предполагает работу с разными источниками данных, высокой нагрузкой и автоматизированными процессами, требуется мощная инфраструктурная поддержка, автоматизация процессов обновления и развертывания новых сервисов.

- **Service Discovery** и **управление конфигурациями:** HashiCorp Consul
- **Управление секретами и шифрованием:** HashiCorp Vault
- **Кэширование:** Redis
- **Очереди сообщений и задач:** RabbitMQ, Celery
- **Логирование и мониторинг:** ELK Stack, Prometheus, Grafana
- **Маршрутизация и балансировка нагрузки:** Traefik
- **Базы данных:** PostgreSQL + TimescaleDB для временных рядов
- **Управление пользователями:** Keycloak.

Ключевая задача на данном этапе — создать удобный **инсталлятор**, который позволит удобно разворачивать все необходимые сервисы.

- Рассматриваются:  
    - **Docker + Kubernetes** - контейнеризация и оркестрация микросервисов.
    - **Ansible + Terraform** - автоматизация развёртывания инфраструктуры.

## Проблемы и вызовы

На текущем этапе есть сложности, которые требуют дальнейшего исследования и тестирования различных решений:

- **Гибкость системы интеграций:**
    - требуется единый формат работы с биржами, API которых часто отличаются
    - Как эффективно кэшировать данные, чтобы не превышать лимиты API?
    - вариативность логики исполнения ордеров усложняет универсальную архитектуру

- **Оптимизация хранения и обработки данных:**
    - Как обеспечить устойчивую работу API при высоких нагрузках?
    - необходимо учитывать большие объемы данных и нагрузку при обработке
    - кэширование может создавать сложности с актуальностью информации

- **Разработка и поддержка торговых стратегий:**
    - реализация алгоритмов требует тестирования и валидации на больших объёмах исторических данных

- **Архитектура микросервисов:**
    - необходимо правильно сбалансировать нагрузку между сервисами
    - обеспечить их отказоустойчивость и гибкость масштабирования

- **Тестирование и стратегия релизов:**
    - Как организовать **интеграционное тестирование** всех компонентов?
    - Как **минимизировать риски** при обновлениях?
