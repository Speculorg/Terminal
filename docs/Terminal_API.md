# Навигация и API Speculorg.Terminal

Навигация и API — это ключевые элементы взаимодействия пользователей и приложений с системой Speculorg.Terminal.

Данный документ описывает, как устроен контекст `Speculorg.Terminal.API`, определяющий все необходимые модели, сервисы и инструменты, необходимые для организации API-доступа и навигации в системе Speculorg.Terminal.

Также, мы рассмотрим реализацию этого контекста в компоненте `Speculorg.Terminal.API.Service`, который обеспечивает механизмы навигации в пользовательском интерфейсе, а также функциональность API для связи внутренних компонентов и внешних сервисов с платформой Speculorg.Terminal.

> - [Система безопасности](Terminal_Security.md)

## Введение

Система **Speculorg.Terminal** ориентирована на удобный и безопасный доступ к широкому спектру функций — от размещения торговых ордеров до аналитических расчётов и интеграций с внешними сервисами. Для этого разработана:

- **API** — предоставляет внешний и внутренний интерфейс к функциональности системы, поддерживает REST- и WebSocket-соединения, версионирование и механизмы аутентификации/авторизации.
- **Удобная навигация** — обеспечивает структурированный интерфейс, упрощающий пользователям поиск нужных разделов и работу с ними.

Данный документ раскрывает устройство контекста `Speculorg.Terminal.API` и его реализацию в виде компонента `Speculorg.Terminal.API.Service`, а также описывает основные модули, поддерживающие навигацию и API-взаимодействие.

---

## Компонент API.Service

`Speculorg.Terminal.API.Service` — это **ContextMicroservice**, отвечающий за маршрутизацию внешних запросов к внутренним микросервисам, а также за предоставление точек входа для UI-навигации в веб-приложении.

### Ключевые функции

- **API Gateway (Traefik)**
    - Является центральной точкой входа в API системы.
    - Балансировка нагрузки и маршрутизация HTTP/HTTPS-запросов к нужным микросервисам.
    - Интеграция с системой безопасности (проверка JWT токенов, OAuth2/OpenID Connect).
    - Ограничение скорости (Rate Limiting) и защита от DDoS.

- **REST и WebSocket**
    - Предоставление REST-эндпоинтов для CRUD-операций и получения данных.
    - WebSocket-каналы для потоковых обновлений (статусы ордеров, лента сделок, уведомления).

- **Версионирование API**
    - Поддержка нескольких версий (`/api/v1/`, `/api/v2/`), чтобы можно было вносить изменения без прерывания работы клиентов.

- **Маршрутизация и фильтрация**
    - Фильтрация и преобразование запросов, интеграция с `Speculorg.Terminal.Security.Service` для авторизации.
    - Приём запросов на публичные API (например, для интеграции с внешними приложениями).

- **Навигационные конечные точки (Frontend Routes)**
    - Передача статических ресурсов (SPA, если используется) и маршрутов для клиентской части.
    - Базовый роутинг UI, если фронтенд развёрнут совместно с API Gateway.

### Особенности

`Speculorg.Terminal.API.Service` реализован как компонент типа `ContextMicroservice`, поэтому:

- Регистрируется в `Speculorg.Terminal.Infrastructure.Service` (Consul).
- Получает инфраструктурные конфигурации.
- Предоставляет API к своим функциям для других сервисов и процессов.
- Обеспечивает динамическое подключение `ContextSection` в виде Модулей.
- Стандартизировано управляется через `Speculorg.Terminal.Management.Service`, который задаёт политики маршрутизации, обновления версий и т.п..
- Обеспечивает интерфейсы безопасности `Speculorg.Terminal.Security.Service`.
- Реализует **CrossCutting (Сквозная функциональность)** для нужд `Speculorg.Terminal.Infrastructure.Service`.

## Модули API.Service

Согласно [Архитектуре компонентов](Terminal_Architecture.md) в Speculorg.Terminal предусмотрены **Модули** (Module), расширяющие функциональность компонентов типа `ContextMicroservice`. Поэтому, некоторые участки логики мы выделили в отдельные подключаемые Модули, чтобы изолировать их управление и настройки.

> **Причины модульности**
> - Чёткое разграничение ответственности (например, отдельный модуль для WebSocket).
> - Возможность подключать/отключать эндпоинты, не затрагивая весь сервис.
> - Упрощённое тестирование и обновление.

### Формат именования

- `Speculorg.Terminal.API.<ModuleName>.Module`

### Примеры модулей

- **Routing.Module**
    - Имя: `Speculorg.Terminal.API.Routing.Module`
    - Назначение: Управление таблицами маршрутизации, фильтрами запросов и т.д.

- **WebSocket.Module**
    - Имя: `Speculorg.Terminal.API.WebSocket.Module`
    - Назначение: Создание и поддержка двусторонних каналов связи. Реализация подписок, потоковых данных.

- **Versioning.Module**
    - Имя: `Speculorg.Terminal.API.Versioning.Module`
    - Назначение: Гибкое управление версиями API, подгрузка старых и новых схем эндпоинтов.

- **FrontendDelivery.Module**
    - Имя: `Speculorg.Terminal.API.FrontendDelivery.Module`
    - Назначение: Обслуживание статических файлов фронтенда и маршрутов клиентского SPA (если используется).

## Управление аспектами Навигации и API

- **Speculorg.Terminal.Management.Service**
    - Определяет конфигурации роутинга (Traefik, Consul) и токенов аутентификации.
    - Управляет обновлениями версий API и параметрами публичных/приватных маршрутов.
    - Обеспечивает аудит обращений к настройкам API (AuditLog).

- **Speculorg.Terminal.Infrastructure.Service**
    - Предоставляет инструменты логирования (ELK), мониторинга (Prometheus/Grafana), хранение конфигураций (Consul).
    - Организует масштабирование и оркестрацию (Kubernetes), проверку состояния API Gateway.
    - Хранит секреты для SSL (Vault), позволяет быстро обновлять сертификаты.

- **Speculorg.Terminal.Security.Service**
    - Проверяет токены и права доступа (RBAC, OAuth2), синхронизируясь с Keycloak.
    - Ограничение запросов (Rate Limit) и защита от злоумышленного трафика (Intrusion Detection).

- **Специфические интеграции** (Speculorg.Terminal.Integration.Service)
    - Использование API ключей, выделенных для внешних сервисов.
    - Настройка маршрутизации запросов к адаптерам внешних бирж, агрегаторов, кошельков.

Таким образом, административные и эксплуатационные функции, связанные с маршрутизацией и навигацией, централизованы в `Speculorg.Terminal.API.Service` и интегрируются с другими службами для полноценной поддержки API и UI.
