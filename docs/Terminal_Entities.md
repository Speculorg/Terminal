
# Сущности Speculorg.Terminal (MVP)

В этом документе перечислены сущности, которые представляют собой ключевые программные объекты системы `Speculorg.Terminal`.

---

## Введение

Сущности в Speculorg.Terminal представляют основные абстракции, моделирующие реальные бизнес-процессы, данные и операции. Они обеспечивают:

- Управление данными.
- Инкапсуляцию бизнес-логики.
- Взаимодействие между компонентами системы.

### Основные роли сущностей

- **Моделирование предметной области:** 
    - Сущности отражают ключевые бизнес-объекты, такие как *активы, ордера, биржи, пользовательские данные*.
- **Централизация данных:** 
    - Единый источник правдивых данных, используемый всеми модулями системы.
- **Инкапсуляция логики:** 
    - Логика управления данными находится внутри сущностей, минимизируя дублирование и упрощая поддержку.
- **Интеграция компонентов:**
    - Обеспечивают взаимодействие между модулями через API (REST, WebSocket).
- **Масштабируемость:** 
    - Разделение ответственности между сущностями поддерживает расширяемость системы.
- **Управление состоянием:** 
    - Каждая сущность контролирует свой жизненный цикл (создание, обновление, архивирование, удаление).

### Принципы проектирования

- **Модульность и изолированность:**
    - Каждая сущность выполняет конкретную задачу.
    - Минимизация зависимостей между сущностями через чётко определённые связи.
- **Типизация данных:**
    - Строгая типизация для обеспечения целостности данных и упрощения интеграции.
- **Управление жизненным циклом:**
    - Логирование изменений (через `AuditLog`) и стандартные атрибуты (`created_at`, `updated_at`, `status`).
- **Безопасность:**
    - Критически важные данные (`SessionToken`, `Secret`) шифруются с использованием AES-256.
    - Контроль доступа через Keycloak и политики безопасности.
- **Масштабируемость и производительность:**
    - Redis используется для временных данных (TTL).
    - Денормализованные поля (например, `snapshot`) ускоряют чтение данных.

### Связи между сущностями

- **Foreign Key и ассоциации:**
    - Логические связи между сущностями оптимизируют взаимодействие (например, связь `Order` с `Market`).
- **Идентификаторы:**
    - Универсальные UUID для уникальной идентификации.
    - Внешние идентификаторы (`external_id`) для интеграций с API.

### Реализация особенностей

1. **Обновление в реальном времени:**
    - Использование WebSocket и RabbitMQ для моментального обновления данных (например, в `OrderBook` и `TradeTape`).
2. **Метаданные:**
    - Сущности включают стандартные атрибуты (`status`, `parameters` в формате JSON), упрощающие конфигурацию под различные сценарии.
3. **Гибкость параметров:**
    - Настраиваемые параметры делают сущности универсальными для разных пользователей.

## Список сущностей

### **UserAccount (Учетная запись пользователя)**

- **Описание**: Унифицированная сущность, объединяющая управление пользователями и их учетными данными. Используется для аутентификации, контроля доступа и настройки профилей.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор пользователя.
    - `email`: Электронная почта пользователя (уникальная, используется для входа).
    - `password_hash`: Хеш пароля пользователя (например, bcrypt, Argon2).
    - `role`: Роль пользователя (`admin`, `trader`, `viewer`).
    - `status`: Статус учетной записи (`active`, `suspended`, `deleted`).
    - `karma`: Карма пользователя для оценки вклада в систему.
    - `preferences`: Настройки пользователя (например, язык интерфейса, уведомления).
    - `auth_type`: Тип аутентификации (`password`, `token`, `api_key`).
    - `api_key`: Ключ API для программного доступа (опционально).
    - `token`: Токен доступа, если используется (например, OAuth2).
    - `scope`: Область действия аутентификации (`global`, `service_specific`).
    - `last_login_at`: Дата и время последнего входа.
    - `last_used_at`: Дата последнего использования учетных данных.
    - `created_at`: Дата и время создания учетной записи.
    - `updated_at`: Дата последнего изменения учетной записи.

- **Связи**:
    - `Portfolio`: Портфели пользователя для управления активами.
    - `Order`: Торговые ордера, связанные с пользователем.
    - `Trade`: История сделок пользователя.
    - `Balance`: Балансы пользователя в системе.
    - `AuditLog`: Логи активности учетной записи.
    - `ExternalService`: Внешние сервисы, связанные с учетными данными.
    - `SecurityPolicy`: Политики безопасности, регулирующие доступ.

- **Операции**:
    - `create_user_account`: Создание новой учетной записи пользователя.
    - `update_user_account`: Обновление профиля и учетных данных пользователя.
    - `authenticate_user`: Аутентификация пользователя с проверкой учетных данных.
    - `reset_password`: Сброс пароля и отправка инструкции на email.
    - `assign_role`: Назначение роли пользователю для управления доступом.
    - `validate_auth`: Проверка валидности учетных данных (пароль, токен или API-ключ).
    - `rotate_credentials`: Ротация ключей API или токенов.
    - `log_activity`: Запись действий пользователя в журнал аудита.
    - `fetch_preferences`: Получение текущих пользовательских настроек.
    - `update_preferences`: Обновление пользовательских предпочтений.
    - `audit_user`: Логирование изменений профиля и учетных данных.
    - `delete_user_account`: Удаление учетной записи пользователя.
    - `export_user_data`: Экспорт данных учетной записи для резервного копирования.
    - `import_user_data`: Импорт данных учетной записи из зашифрованного файла.

### **Session (Сессия)**

- **Описание**: Сущность представляет активную сессию пользователя. Используется для аутентификации, отслеживания активности и управления безопасностью.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор сессии.
    - `user_id`: Идентификатор пользователя, связанного с сессией.
    - `token`: Уникальный токен сессии, используемый для аутентификации.
    - `ip_address`: IP-адрес устройства пользователя, инициировавшего сессию.
    - `user_agent`: Информация о клиенте (браузер, операционная система, версия приложения).
    - `created_at`: Дата и время начала сессии.
    - `expires_at`: Дата и время истечения срока действия сессии.
    - `last_activity_at`: Время последней активности пользователя в рамках сессии.
    - `status`: Текущий статус сессии (`active`, `terminated`, `expired`).
    - `scope`: Область действия сессии (`global`, `terminal`, `cms`, `api`).

- **Связи**:
    - `User`: Пользователь, связанный с данной сессией.
    - `SecurityPolicy`: Политики безопасности, применяемые к сессии (например, ограничения по IP).
    - `AuditLog`: Записи аудита, связанные с действиями в рамках данной сессии.

- **Операции**:
    - `create_session`: Создание новой сессии при успешной аутентификации пользователя.
    - `terminate_session`: Завершение сессии (по инициативе пользователя, из-за нарушения безопасности или истечения срока действия).
    - `fetch_active_sessions`: Получение списка всех активных сессий пользователя.
    - `validate_session`: Проверка токена сессии на действительность и срок действия.
    - `refresh_session`: Обновление срока действия токена сессии при активности пользователя.
    - `log_session_activity`: Логирование действий, выполненных в рамках сессии.
    - `fetch_session_by_token`: Получение данных сессии по токену для проверки аутентификации.
    - `audit_session`: Создание записи в журнале аудита при изменении статуса сессии.

### **SessionToken (Токен сессии)**

 - **Описание**: Токен, используемый для аутентификации пользователей и управления их сессиями. Обеспечивает доступ к ресурсам системы в рамках активной сессии, гарантируя безопасность и контроль.

 - **Атрибуты**:
     - `uuid`: Уникальный идентификатор токена.
     - `user_id`: Идентификатор пользователя, связанного с токеном.
     - `token_value`: Значение токена (зашифрованное).
     - `issued_at`: Дата и время выдачи токена.
     - `expires_at`: Дата и время истечения срока действия токена.
     - `status`: Текущий статус токена (`active`, `revoked`, `expired`).
     - `ip_address`: IP-адрес устройства, инициировавшего сессию.
     - `user_agent`: Информация о клиенте (браузер, ОС, приложение).
     - `scope`: Область действия токена (`read_only`, `full_access`, `api_access`).
     - `last_used_at`: Дата и время последнего использования токена.
     - `source`: Источник создания токена (`global`, `terminal`, `cms`, `api`).

 - **Связи**:
     - `User`: Пользователь, связанный с токеном.
     - `Session`: Активная сессия, связанная с токеном.
     - `AuditLog`: Логи, фиксирующие использование токена.

 - **Операции**:
     - `generate_token`: Генерация нового токена для аутентификации.
     - `validate_token`: Проверка токена на действительность и срок действия.
     - `revoke_token`: Отзыв токена, делая его недействительным.
     - `refresh_token`: Обновление токена для продления срока действия сессии.
     - `fetch_active_tokens`: Получение списка активных токенов для пользователя.
     - `audit_token`: Логирование операций с токенами для мониторинга и анализа.
     - `expire_tokens`: Массовое завершение срока действия устаревших токенов.
     - `export_token_logs`: Экспорт информации о токенах и их использовании для анализа.
     - `monitor_token_activity`: Отслеживание активности токенов в реальном времени для выявления подозрительных действий.

### **Role (Роль)**

- **Описание**: Роль определяет уровень доступа пользователя в системе и предоставляет набор разрешений для взаимодействия с её компонентами. Используется для управления правами пользователей и разграничения их доступа.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор роли.
    - `name`: Название роли (например, `admin`, `trader`, `viewer`, `risk_manager`).
    - `permissions`: Список разрешений, связанных с ролью (например, `manage_users`, `execute_trades`, `view_reports`).
    - `description`: Описание роли, её целей и ограничений.
    - `scope`: Область действия роли (`global`, `module`, `user_specific`).
    - `priority`: Приоритет роли, используемый для разрешения конфликтов при множественных назначениях.
    - `status`: Статус роли (`active`, `archived`).
    - `created_at`: Дата и время создания роли.
    - `updated_at`: Дата последнего изменения роли.

- **Связи**:
    - `User`: Пользователи, связанные с данной ролью.
    - `SecurityPolicy`: Политики безопасности, ассоциированные с ролью.
    - `Module`: Модули системы, доступ к которым регулируется ролью.
    - `AuditLog`: Записи аудита, связанные с действиями пользователей в рамках их роли.

- **Операции**:
    - `create_role`: Создание новой роли с заданными разрешениями.
    - `assign_role_to_user`: Назначение роли пользователю.
    - `revoke_role_from_user`: Отзыв роли у пользователя.
    - `update_role`: Обновление названия, описания или разрешений роли.
    - `delete_role`: Удаление роли, не связанной с активными пользователями.
    - `fetch_roles`: Получение списка ролей с возможностью фильтрации по статусу и области действия.
    - `validate_permissions`: Проверка разрешений роли на соответствие установленным требованиям.
    - `audit_role_changes`: Логирование изменений, связанных с ролями, для целей безопасности и контроля.
    - `export_role`: Экспорт роли в формате JSON для резервного копирования или миграции.
    - `import_role`: Импорт роли из файла JSON в систему.

### **Permission (Разрешение)**

- **Описание**: Разрешение определяет конкретное право на выполнение действия или доступ к ресурсу в системе. Используется для управления доступом на более детальном уровне, чем роли.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор разрешения.
    - `name`: Название разрешения (например, `create_order`, `view_reports`, `manage_users`).
    - `description`: Краткое описание действия или ресурса, на который распространяется разрешение.
    - `category`: Категория разрешения (например, `trading`, `administration`, `analytics`).
    - `scope`: Область действия разрешения (`global`, `module`, `resource_specific`).
    - `status`: Статус разрешения (`active`, `deprecated`).
    - `created_at`: Дата и время создания разрешения.
    - `updated_at`: Дата последнего изменения разрешения.

- **Связи**:
    - `Role`: Роли, которым назначено данное разрешение.
    - `User`: Пользователи, напрямую связанные с данным разрешением.
    - `Module`: Модули или компоненты системы, для которых применяется разрешение.
    - `AuditLog`: Логи, фиксирующие использование разрешения.

- **Операции**:
    - `create_permission`: Создание нового разрешения с заданными параметрами.
    - `assign_permission_to_role`: Назначение разрешения роли.
    - `assign_permission_to_user`: Назначение разрешения пользователю.
    - `revoke_permission_from_role`: Удаление разрешения из роли.
    - `revoke_permission_from_user`: Удаление разрешения у пользователя.
    - `update_permission`: Обновление названия, описания или категории разрешения.
    - `delete_permission`: Удаление устаревшего или неиспользуемого разрешения.
    - `fetch_permissions`: Получение списка разрешений с возможностью фильтрации (по `category`, `scope`, `status`).
    - `validate_permission`: Проверка корректности разрешения перед назначением.
    - `audit_permission_changes`: Логирование изменений, связанных с разрешением.
    - `export_permission`: Экспорт разрешения в JSON для резервного копирования.
    - `import_permission`: Импорт разрешения из файла JSON в систему.

### **SecurityPolicy (Политика безопасности)**

- **Описание**: Политика безопасности управляет правами доступа, аутентификацией, авторизацией и другими аспектами безопасности пользователей в системе. Предназначена для обеспечения надёжной и гибкой системы контроля доступа.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор политики безопасности.
    - `policy_name`: Название политики безопасности (например, `AdminPolicy`, `TraderPolicy`, `ReadOnlyPolicy`).
    - `rules`: Набор правил политики, определяющих доступные действия и области доступа (например, `allow_api_access`, `restrict_delete_order`).
    - `scope`: Область действия политики (`global`, `role_based`, `user_specific`).
    - `assigned_to`: Идентификаторы ролей или пользователей, на которых распространяется политика.
    - `priority`: Приоритет политики (число, определяющее порядок применения в случае конфликта).
    - `status`: Статус политики (`active`, `inactive`).
    - `created_at`: Дата и время создания политики.
    - `updated_at`: Дата последнего изменения политики.

- **Связи**:
    - `User`: Пользователи, на которых распространяется политика.
    - `Role`: Роли, связанные с политикой безопасности.
    - `Configuration`: Настройки системы, влияющие на правила политики безопасности.
    - `AuditLog`: Логи, фиксирующие действия, связанные с применением политики.

- **Операции**:
    - `create_policy`: Создание новой политики безопасности с заданными правилами.
    - `update_policy`: Обновление существующей политики (например, добавление новых правил).
    - `assign_policy`: Назначение политики роли или пользователю.
    - `remove_policy`: Удаление политики безопасности из системы.
    - `validate_policy`: Проверка корректности правил политики перед её применением.
    - `fetch_policies`: Получение списка всех политик с возможностью фильтрации (по `scope`, `status`).
    - `enforce_policy`: Применение политики для заданного пользователя или роли в реальном времени.
    - `audit_policy`: Логирование событий, связанных с политиками безопасности.
    - `export_policy`: Экспорт политики безопасности в JSON для резервного копирования или переноса.
    - `import_policy`: Импорт политики из файла JSON в систему.

### **Secret (Секрет)**

- **Описание**: Конфиденциальная информация, такая как пароли, ключи API и токены, требующая защиты и строгого контроля доступа. Используется для безопасного взаимодействия с внешними сервисами и модулями.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор секрета.
    - `name`: Название секрета (например, `Binance API Key`, `Database Password`).
    - `value`: Значение секрета (зашифрованное).
    - `type`: Тип секрета (`api_key`, `password`, `token`, `certificate`).
    - `scope`: Область применения секрета (`global`, `module_specific`, `user_specific`).
    - `created_at`: Дата и время создания секрета.
    - `updated_at`: Дата последнего обновления секрета.
    - `accessed_at`: Дата и время последнего доступа к секрету.
    - `status`: Статус секрета (`active`, `revoked`, `expired`).
    - `owner_id`: Идентификатор пользователя или системы, управляющего секретом.

- **Связи**:
    - `User`: Пользователь, управляющий секретом (если применимо).
    - `ExternalService`: Внешний сервис, для которого используется секрет.
    - `AuditLog`: Логи доступа и изменений секрета.

- **Операции**:
    - `create_secret`: Создание нового секрета с заданными параметрами.
    - `update_secret`: Обновление значения или метаданных секрета.
    - `revoke_secret`: Отзыв секрета, делая его недоступным для использования.
    - `fetch_secret`: Получение значения секрета с проверкой прав доступа.
    - `validate_secret`: Проверка валидности и актуальности секрета.
    - `rotate_secret`: Замена значения секрета на новое (ротация ключей API или паролей).
    - `audit_secret`: Логирование доступа, создания или изменения секрета.

    - `market_cap`: Рыночная капитализация актива (в базовой валюте, например, USD).
    - `type`: Тип актива (например, `Crypto`, `Stock`, `Bond`, `ETF`).
    - `exchange_id`: Идентификатор биржи или площадки, на которой торгуется актив.
    - `status`: Статус актива (`active`, `suspended`, `delisted`).
    - `created_at`: Дата и время добавления актива в систему (тип: `datetime` с UTC).
    - `updated_at`: Дата и время последнего обновления данных.

- **Связи**:
    - `Portfolio`: Актив используется для расчётов и управления портфелями пользователей.

    - `update_asset`: Обновление текущих данных актива (цена, статус, объём и др.).
    - `fetch_market_data`: Получение рыночных данных для актива из интеграционных API (например, CoinMarketCap, Binance).
    - `calculate_trend`: Анализ трендов цены и объёма для актива за заданный период.
    - `sync_with_terminal`: Синхронизация данных актива с Speculorg.Terminal.
    - `generate_report`: Генерация отчёта о состоянии актива для аналитики и прогнозов.
    - `validate_asset`: Проверка консистентности данных актива (например, соответствие типу и бирже).

    - `price_change_percentage`: Изменение цены базового актива относительно котируемого в процентах за определённый период.
    - `status`: Статус торговой пары (`active`, `suspended`, `delisted`).
    - `created_at`: Дата и время добавления пары в систему.
    - `updated_at`: Дата и время последнего обновления данных пары.

- **Связи**:
    - `BaseAsset`: Связь с базовым активом через `base_asset_id`.

### **Order (Ордер)**

- **Описание**: Ордер представляет собой заявку на покупку или продажу актива в рамках торговой пары.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор ордера.
    - `user_id`: Идентификатор пользователя, разместившего ордер.
    - `trading_pair_id`: Идентификатор торговой пары, к которой относится ордер.
    - `type`: Тип ордера (`limit`, `market`, `stop`, `trailing_stop`).
    - `side`: Сторона сделки (`buy`, `sell`).
    - `quantity`: Количество базового актива, указанное в ордере (тип: `decimal`).
    - `price`: Цена ордера (для лимитных и условных ордеров; тип: `decimal`).
    - `status`: Текущий статус ордера (`new`, `partially_filled`, `filled`, `canceled`, `expired`).
    - `filled_quantity`: Количество актива, которое уже исполнено.
    - `fee`: Комиссия за исполнение ордера (тип: `decimal`).
    - `fee_asset_id`: Идентификатор актива, в котором выплачивается комиссия.
    - `exchange_id`: Идентификатор биржи, на которой размещён ордер.
    - `created_at`: Дата и время создания ордера.
    - `updated_at`: Дата и время последнего изменения статуса ордера.
    - `expires_at`: Дата и время истечения срока действия ордера (опционально).

- **Связи**:
    - `User`: Связь с пользователем через `user_id`.
    - `TradingPair`: Связь с торговой парой через `trading_pair_id`.
    - `Speculorg.Terminal`: Интеграция для управления торговыми операциями.
    - `OrderHistory`: Логи изменений и действий, связанных с ордером.
    - `MarketData`: Связь для получения информации о ценах и объёмах.

- **Операции**:
    - `create_order`: Создание нового ордера в системе.
    - `update_order`: Обновление параметров ордера (например, изменение статуса или заполненного количества).
    - `cancel_order`: Отмена активного ордера.
    - `execute_order`: Исполнение ордера с обновлением статуса и заполненного количества.
    - `fetch_order_status`: Получение текущего статуса ордера с биржи.
    - `calculate_fee`: Расчёт комиссии за исполнение ордера.
    - `validate_order`: Проверка корректности данных ордера перед размещением.
    - `sync_with_terminal`: Синхронизация данных ордера с системой Speculorg.Terminal.
    - `generate_report`: Создание отчёта по истории ордера для аналитики.
    - `audit_log`: Запись всех изменений ордера для целей контроля и аудита.

    - `side`: Сторона сделки (`buy`, `sell`).

    - `price`: Цена, по которой была исполнена сделка (тип: `decimal`).
    - `fee`: Комиссия, взятая за выполнение сделки (тип: `decimal`).
    - `fee_asset_id`: Идентификатор актива, в котором выплачивается комиссия.
    - `total_value`: Общая стоимость сделки (например, `quantity * price`).
    - `exchange_id`: Идентификатор биржи, на которой была выполнена сделка.
    - `status`: Статус сделки (`completed`, `failed`, `pending`).
    - `trade_time`: Время выполнения сделки (тип: `datetime` с UTC).
    - `created_at`: Дата и время добавления записи о сделке в систему.
    - `updated_at`: Дата и время последнего обновления данных о сделке.

    - `User`: Связь с пользователем через `user_id`.
    - `MarketData`: Используется для получения информации о рыночных условиях во время сделки.
    - `Speculorg.Terminal`: Интеграция для анализа и отчётности по сделкам.

- **Операции**:
    - `create_trade`: Добавление новой записи о сделке в систему.
    - `update_trade`: Обновление параметров сделки (например, статуса или комиссии).
    - `fetch_trade_details`: Получение полной информации о сделке из биржевого API.
    - `calculate_total_value`: Расчёт общей стоимости сделки (с учётом количества и цены).
    - `analyze_trade`: Проведение анализа сделки для выявления трендов или отклонений.
    - `sync_with_terminal`: Синхронизация данных сделки с системой Speculorg.Terminal.
    - `generate_report`: Создание отчёта по сделке для аналитики и финансового учёта.

### **Signal (Сигнал)**

- **Описание**: Уведомление или триггер, основанный на заданных условиях, рыночных индикаторах или алгоритмах. Используется для предоставления рекомендаций по торговле или автоматизации действий.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор сигнала.
    - `type`: Тип сигнала (`buy`, `sell`, `hold`, `alert`).
    - `provider_id`: Идентификатор источника сигнала.
    - `strategy_id`: Идентификатор стратегии, на основе которой был сгенерирован сигнал.
    - `asset_id`: Идентификатор актива, к которому относится сигнал.
    - `price`: Цена актива на момент генерации сигнала (тип: `decimal`).
    - `target_price`: Целевая цена, при достижении которой сигнал считается выполненным.
    - `stop_loss`: Уровень Stop-Loss для сигнала.
    - `confidence_level`: Уровень уверенности в сигнале (например, процент вероятности исполнения).
    - `status`: Статус сигнала (`active`, `triggered`, `expired`, `canceled`).
    - `timestamp`: Время генерации сигнала (тип: `datetime` с UTC).
    - `expires_at`: Время истечения срока действия сигнала (опционально).
    - `created_at`: Дата и время добавления сигнала в систему.
    - `updated_at`: Дата и время последнего обновления сигнала.

- **Связи**:
    - `Asset`: Связь с активом, к которому относится сигнал.
    - `User`: Если сигнал создан пользователем вручную.
    - `Strategy`: Связь с торговой стратегией, сгенерировавшей сигнал.
    - `Speculorg.Terminal`: Интеграция для автоматизации торговли на основе сигналов.
    - `MarketData`: Используется для проверки условий выполнения сигнала.

- **Операции**:
    - `create_signal`: Создание нового торгового сигнала.
    - `fetch_signals`: Получение списка активных или исторических сигналов.
    - `analyze_signal`: Анализ сигнала для оценки его точности и эффективности.
    - `trigger_signal`: Пометка сигнала как сработавшего при достижении условий.
    - `subscribe_to_signal`: Подписка пользователя на получение уведомлений о сигнале.
    - `validate_signal`: Проверка корректности и актуальности данных сигнала.
    - `sync_with_terminal`: Синхронизация сигналов с системой Speculorg.Terminal для выполнения действий.
    - `generate_report`: Создание отчёта о результатах выполнения сигналов.
    - `audit_log`: Запись изменений сигнала для контроля и аудита.

### **Strategy (Стратегия)**

- **Описание**: Набор правил и алгоритмов, определяющий автоматизированные торговые действия на основе рыночных данных и сигналов.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор стратегии.
    - `user_id`: Идентификатор пользователя, создавшего стратегию.
    - `name`: Название стратегии.
    - `description`: Описание логики и алгоритмов стратегии.
    - `type`: Тип стратегии (`trend_following`, `mean_reversion`, `arbitrage` и т.д.).
    - `parameters`: Параметры настройки стратегии (например, пороги срабатывания, лимиты риска).
    - `status`: Статус стратегии (`active`, `paused`, `stopped`, `draft`).
    - `execution_frequency`: Частота выполнения стратегии (`real_time`, `hourly`, `daily`).
    - `performance_metrics`: Метрики производительности стратегии.
    - `created_at`: Дата и время добавления стратегии в систему.
    - `updated_at`: Дата последнего обновления стратегии.

- **Связи**:
    - `User`: Связь с пользователем, которому принадлежит стратегия.
    - `Signal`: Связь с сигналами, используемыми для принятия решений в рамках стратегии.
    - `Order`: Связь с ордерами, созданными стратегией.
    - `Trade`: Связь с исполненными сделками, результатами работы стратегии.
    - `Speculorg.Terminal`: Интеграция для анализа и автоматизации выполнения стратегии.
    - `Speculorg.AI`: Использование для прогнозирования и оптимизации параметров стратегии.

- **Операции**:
    - `create_strategy`: Создание новой стратегии с заданными параметрами.
    - `update_strategy`: Обновление параметров или описания существующей стратегии.
    - `delete_strategy`: Удаление стратегии из системы (с предварительным архивированием результатов).
    - `execute_strategy`: Запуск выполнения стратегии с учётом текущих рыночных данных и сигналов.
    - `pause_strategy`: Приостановка выполнения стратегии.
    - `resume_strategy`: Возобновление выполнения ранее приостановленной стратегии.
    - `fetch_strategy_results`: Получение результатов выполнения стратегии, включая метрики производительности.
    - `analyze_performance`: Анализ производительности стратегии на основе исторических данных и текущих результатов.
    - `validate_strategy`: Проверка корректности логики и параметров стратегии перед её запуском.
    - `audit_log`: Запись всех изменений и операций, связанных со стратегией, для целей контроля.

### **RiskManager (Менеджер рисков)**

- **Описание**: Управляет процессами мониторинга, анализа и контроля рисков в режиме реального времени. Отвечает за выполнение действий, основанных на RiskPolicy.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор менеджера рисков.
    - `user_id`: Идентификатор пользователя, для которого работает менеджер.
    - `policy_id`: Идентификатор применяемой RiskPolicy.
    - `current_drawdown`: Текущее снижение стоимости портфеля (тип: `decimal`).
    - `margin_utilization`: Текущий уровень использования маржи (тип: `decimal`).
    - `open_positions`: Список идентификаторов открытых позиций.
    - `status`: Текущий статус менеджера (`active`, `suspended`).
    - `created_at`: Дата создания менеджера.
    - `updated_at`: Дата последнего обновления.

- **Связи**:
    - `RiskPolicy`: Применяемая политика управления рисками.
    - `Portfolio`: Используется для анализа текущих позиций.

- **Операции**:
    - `initialize_manager`: Инициализация менеджера для нового пользователя.
    - `evaluate_risks`: Оценка текущего уровня рисков по параметрам RiskPolicy.
    - `apply_policy`: Применение ограничений и правил, указанных в RiskPolicy.
    - `adjust_positions`: Автоматическая корректировка позиций для соблюдения параметров.
    - `trigger_stop_loss`: Выполнение действий при превышении допустимых потерь.

### **RiskPolicy (Политика управления рисками)**

- **Описание**: Определяет основные ограничения и правила управления рисками, включая пороговые значения убытков и прибыли. Применяется на уровне пользователя или стратегии.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор политики.
    - `user_id`: Идентификатор пользователя, к которому привязана политика.
    - `strategy_id`: Идентификатор стратегии, связанной с политикой (опционально).
    - `max_drawdown`: Максимально допустимый уровень потерь (тип: `decimal`).
    - `stop_loss`: Уровень защиты для автоматической продажи актива (тип: `decimal`).
    - `take_profit`: Уровень прибыли для автоматической фиксации доходов (тип: `decimal`).
    - `max_open_positions`: Максимальное количество открытых позиций.
    - `risk_tolerance`: Уровень риска (`low`, `medium`, `high`).
    - `status`: Статус политики (`active`, `archived`).
    - `created_at`: Дата и время создания политики.
    - `updated_at`: Дата последнего обновления.

- **Связи**:
    - `User`: Привязка к конкретному пользователю.
    - `Strategy`: Используется для стратегий с заданной политикой.

- **Операции**:
    - `create_policy`: Создание новой политики.
    - `update_policy`: Обновление параметров политики.
    - `delete_policy`: Удаление политики.
    - `validate_policy`: Проверка корректности параметров политики.

### **RiskMetric (Метрика риска)**

- **Описание**: Показатели, оценивающие уровень риска портфеля, актива или стратегии. Используются для анализа рисков и принятия решений в торговле.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор метрики риска.
    - `asset_id`: Идентификатор актива, для которого рассчитана метрика (опционально).
    - `portfolio_id`: Идентификатор портфеля, связанного с метрикой (опционально).
    - `metric_name`: Название метрики риска (например, `VaR`, `Sharpe Ratio`, `Sortino Ratio`, `Max Drawdown`).
    - `value`: Значение метрики (тип: `decimal`).
    - `timeframe`: Таймфрейм, для которого рассчитана метрика (`1d`, `1w`, `1m` и т.д.).
    - `parameters`: Дополнительные параметры расчёта (например, уровень доверия для `VaR`).
    - `source`: Источник данных для расчёта метрики (например, `MarketData`, `ExternalService`).
    - `calculated_at`: Дата и время последнего расчёта метрики.
    - `status`: Статус метрики (`active`, `archived`).

- **Связи**:
    - `Asset`: Актив, для которого рассчитана метрика.
    - `Portfolio`: Портфель, связанный с метрикой.
    - `RiskProfile`: Профиль риска, на который влияет метрика.
    - `Speculorg.Terminal`: Использование метрик риска для мониторинга и управления стратегиями.
    - `MarketData`: Данные, использованные для расчёта метрики.

- **Операции**:
    - `calculate_risk_metric`: Расчёт метрики риска на основе входных данных.
    - `fetch_risk_metrics`: Получение списка метрик риска для заданного актива, портфеля или профиля.
    - `validate_risk_metric`: Проверка корректности рассчитанной метрики.
    - `update_risk_metric`: Обновление значения метрики при изменении данных.
    - `store_risk_metric`: Сохранение рассчитанных метрик в базу данных.
    - `export_risk_metrics`: Экспорт метрик риска в CSV или JSON для внешнего анализа.
    - `analyze_risk_trends`: Анализ изменения метрик риска во времени.
    - `compare_risk_metrics`: Сравнение метрик риска для разных активов, портфелей или таймфреймов.
    - `generate_risk_report`: Создание отчёта на основе метрик риска для стратегии или портфеля.

### **RiskAlert (Предупреждение о риске)**

- **Описание**: Генерирует уведомления для пользователя о превышении установленных параметров риска.

- **Атрибуты**:

    - `user_id`: Идентификатор пользователя, для которого создано предупреждение.
    - `policy_id`: Идентификатор политики, связанной с предупреждением.
    - `type`: Тип предупреждения (`drawdown_limit`, `margin_limit`, `stop_loss_triggered`).
    - `message`: Описание предупреждения.

    - `status`: Статус предупреждения (`active`, `resolved`).

- **Связи**:
    - `RiskPolicy`: Политика, связанная с предупреждением.

### **Context (Контекст)**

- **Описание**: Контекст в системе Speculorg.Terminal представляет изолированный домен, обслуживающий конкретную область бизнес-логики. Он отвечает за выполнение строго определённых задач, связанных с предметной областью, таких как торговля, аналитика или управление активами.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор Контекста.
    - `owner`: Идентификатор владельца.
    - `name`: Краткое название Контекста (например, `Trading`, `Analytics`).
    - `version`: Версия Контекста (например, `1.0.0`).
    - `description`: Текстовое описание задач и функциональности Контекста.
    - `status`: Текущий статус Контекста (`active`, `inactive`).
    - `created_at`: Метка времени создания.
    - `updated_at`: Метка времени последнего обновления параметров.
    - `priority`: Уровень приоритета (например, `high`, `medium`, `low`).
    - `sections`: Список Секций ContextSection.
    - `dependencies`: Список зависимостей.
    - `metadata`: Дополнительные параметры в формате JSON.

- **Связи**:
    - **Внутренние:**
        - `ContextMicroservice`: Микросервис, который реализует функциональность этот Контекст.
        - `ContextSection`: Секции, доступные для этого Контекста (например, модуль управления портфелем, или модуль управления Адаптерами).
        - `Entities`: Сущности, управляемые или используемые в рамках этого Контекста.
        - `Events`: События, порождаемые Контекстом.
    - **Внешние:**
        - `Speculorg.Terminal`: Пользователь и процессы использующие функциональность данного Контекста.
        - `APIs`: Интерфейсы Контекста, предоставляемые для других систем или модулей.
        - `Speculorg.Terminal.Management.Service`: Управление жизненным циклом.
        - `Speculorg.Terminal.Infrastructure.Service`: Логирование, мониторинг, управление конфигурацией.
        - `Speculorg.Terminal.Security.Service`: Контроль доступа и операций.

- **Операции**:
    - `create_context`: Создание нового Контекста.
    - `update_context`: Обновление данных и конфигурации Контекста.
    - `delete_context`: Деактивация или удаление Контекста из системы.
    - `add_section`: Добавление новой Секции в Контекст.
    - `remove_section`: Удаление Секции из Контекста.
    - `fetch_sections`: Получение списка Секций, связанных с Контекстом.

### **ContextSection (Секция Контекста)**

- **Описание**: Логическая часть Контекста, представляющая собой модуль для выполнения специфичных подзадач. Секции объединяют бизнес-логику в пределах Контекста и предоставляют возможность модульного расширения функциональности.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор Секции.
    - `owner`: Идентификатор владельца.
    - `context_id`: Идентификатор родительского Контекста.
    - `name`: Название Секции (например, `OrderManagement`, `RiskAnalysis`).
    - `version`: Версия Секции (например, `1.0.0`).
    - `description`: Краткое описание задач и функциональности Секции.
    - `status`: Текущий статус Секции (`active`, `inactive`).
    - `created_at`: Метка времени создания.
    - `updated_at`: Метка времени последнего обновления параметров.
    - `priority`: Уровень приоритета (например, `high`, `medium`, `low`).
    - `dependencies`: Список зависимостей.
    - `metadata`: Дополнительные параметры в формате JSON.

- **Связи**:
    - **Внутренние:**
        - `Context`: Родительский Контекст, частью которого является Секция.
        - `ContextMicroservice`: Компонент, использующий функциональность данной Секции.
        - `Module`: Модуль, реализующий функциональность данной Секции.
        - `Entities`: Сущности, управляемые или используемые в рамках Секции.
        - `Events`: События, порождаемые Секцией.
    - **Внешние:**
        - `Speculorg.Terminal`: Пользователь и процессы использующие функциональность данной Секции.
        - `APIs`: Интерфейсы, предоставляемые Секцией для других систем.
        - `Speculorg.Terminal.Management.Service`: Управление жизненным циклом Секции.
        - `Speculorg.Terminal.Infrastructure.Service`: Логирование, мониторинг и управление конфигурацией.
        - `Speculorg.Terminal.Security.Service`: Контроль доступа и операций.

- **Операции**:
    - `create`: Создание новой Секции в рамках Контекста.
    - `delete`: Удаление Секции, если она больше не используется.
    - `enable`: Активация Секции.
    - `disable`: Деактивация Секции.
    - `update`: Обновление конфигурации или версии Секции.
    - `monitor`: Отслеживание состояния Секции (загрузка, выполнение задач).
    - `metrics`: Получение метрик производительности и статистики.
    - `audit`: Логирование операций и изменений для аудита.
    - `configure`: Управление параметрами Секции.

### **ExternalService (Внешний сервис)**

- **Описание**: Внешний сервис — это абстракция, представляющая интеграцию с внешними системами, такими как биржи, агрегаторы данных, платформы сигналов или криптовалютные кошельки. Каждый Внешний сервис изолирован и предоставляет функциональность через адаптеры, обеспечивая надёжный обмен данными между Speculorg.Terminal и сторонними API.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор Внешнего сервиса.
    - `owner`: Идентификатор владельца.
    - `version`: Версия Внешнего сервиса (например, `1.0.0`).
    - `name`: Название Внешнего сервиса (например, `MEXC`, `CoinMarketCap`).
    - `type`: Тип сервиса (`exchange`, `aggregator`, `wallet`, `signal`).
    - `api_endpoint`: Основной URL-адрес для взаимодействия с API сервиса.
    - `api_version`: Версия API (например, `v1`, `v2`).
    - `auth_method`: Метод аутентификации (`api_key`, `oauth2`, `none`).
    - `rate_limit`: Лимиты запросов к API (например, `1000 requests/minute`).
    - `status`: Текущий статус сервиса (`active`, `maintenance`, `deprecated`).
    - `created_at`: Метка времени добавления сервиса в систему.
    - `updated_at`: Метка времени последнего обновления параметров.
    - `sections`: Список Секций ExternalServiceSection.
    - `dependencies`: Список зависимостей.
    - `metadata`: Дополнительные параметры в формате JSON.
    - `documentation_url`: URL на техническую документацию сервиса.

- **Связи**:
    - **Внутренние:**
        - `ExternalServiceAdapter`: Адаптер, который реализуют связь с API данного сервиса.
        - `ExternalServiceSection`: Секции, доступные для этого Внешнего сервиса (например, модуль спотового рынка для биржи, или модуль глобальных метрик для агрегатора).
        - `Entities`: Сущности, управляемые или используемые в рамках этого Внешнего сервиса.
        - `Events`: События, порождаемые Внешним сервисом.
    - **Внешние:**
        - `Speculorg.Terminal`: Пользователь и процессы использующие функциональность данного Внешнего сервиса.

### **APIRequest (Запрос к API)**

- **Описание**: Представляет запрос к внешнему или внутреннему API для получения данных, управления ордерами или выполнения других операций. Сущность фиксирует параметры, результат и метрики запроса для последующего анализа и аудита.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор запроса.

    - `external_service_id`: Идентификатор внешнего сервиса, к которому отправлен запрос.
    - `endpoint`: API-метод, к которому обращается система (например, `/market_data`, `/order/create`).
    - `http_method`: HTTP-метод, используемый для запроса (`GET`, `POST`, `PUT`, `DELETE`).
    - `parameters`: Параметры запроса (например, фильтры или тело запроса в формате JSON).
    - `response_status`: HTTP-статус ответа от API (`200`, `400`, `500` и т.д.).
    - `response_time`: Время обработки запроса в миллисекундах.
    - `response_data`: Ответные данные от API (в формате JSON, если запрос успешен).
    - `error_message`: Описание ошибки (если запрос завершился неуспешно).
    - `timestamp`: Дата и время отправки запроса (тип: `datetime` с UTC).

- **Связи**:
    - `User`: Связь с пользователем через `user_id`, если запрос инициирован пользователем.
    - `ExternalService`: Связь с внешним сервисом через `external_service_id`.
    - `Speculorg.Terminal`: Интеграция для управления запросами, связанными с торговыми операциями и рыночными данными.

- **Операции**:
    - `create_api_request`: Создание новой записи запроса к API.
    - `fetch_api_response`: Получение ответа от API и сохранение в `response_data`.
    - `log_api_request`: Логирование всех параметров запроса для аудита.
    - `retry_api_request`: Повторная отправка запроса в случае ошибки.
    - `analyze_api_performance`: Анализ времени отклика и частоты ошибок для оптимизации интеграции.

### **Ticker (Тикер)**

- **Описание**: Тикер предоставляет текущую информацию о рыночной цене актива, объёме торгов и других метриках в реальном времени. Используется для анализа рыночных данных и принятия решений.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор тикера.
    - `asset_id`: Идентификатор актива, связанного с тикером.
    - `price`: Текущая цена актива (тип: `decimal`, высокая точность для финансовых расчётов).
    - `volume`: Объём торгов за последний период (например, 24 часа).
    - `price_change_percentage`: Изменение цены в процентах за определённый период.
    - `high`: Максимальная цена актива за указанный период.
    - `low`: Минимальная цена актива за указанный период.
    - `timestamp`: Дата и время последнего обновления данных (тип: `datetime` с UTC).
    - `source`: Источник данных тикера (например, `Binance`, `CoinMarketCap`).

- **Связи**:
    - `Asset`: Актив, связанный с тикером.
    - `ExternalService`: Внешние сервисы, предоставляющие данные для тикера.
    - `Speculorg.Terminal`: Интеграция для отображения данных тикера в реальном времени.
    - `MarketData`: Исторические данные рынка, связанные с тикером.

- **Операции**:
    - `fetch_ticker_data`: Получение данных тикера из внешнего API.
    - `subscribe_to_ticker`: Подписка на обновления данных тикера в реальном времени.
    - `analyze_ticker`: Анализ данных тикера для выявления трендов и рыночных сигналов.
    - `store_ticker_data`: Сохранение данных тикера для последующего анализа.
    - `validate_ticker_data`: Проверка корректности полученных данных тикера.
    - `generate_ticker_report`: Создание отчёта на основе данных тикера (например, изменения цены, объёмы торгов).

### **OrderBook (Стакан заявок, Level 2)**

- **Описание**: Информация о текущих ордерах на покупку и продажу для актива (Level 2). Используется для анализа рыночной ликвидности, определения динамики спроса и предложения, а также поддержки торговых стратегий.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор стакана заявок.
    - `asset_id`: Идентификатор актива, для которого собран стакан.
    - `bids`: Список текущих заявок на покупку, упорядоченных по цене убывания (формат: массив объектов с полями `price`, `quantity`).
    - `asks`: Список текущих заявок на продажу, упорядоченных по цене возрастания (формат: массив объектов с полями `price`, `quantity`).
    - `spread`: Разница между лучшими ценами покупки (`highest bid`) и продажи (`lowest ask`).
    - `depth`: Общее количество доступных объёмов на покупку и продажу в стакане.
    - `timestamp`: Время последнего обновления данных (тип: `datetime` с UTC).
    - `source`: Источник данных (например, `Binance`, `KuCoin`, `Coinbase`).

- **Связи**:
    - `Asset`: Актив, для которого собран стакан заявок.
    - `MarketData`: Рыночные данные, связанные с динамикой заявок.
    - `Speculorg.Terminal`: Использование данных стакана в реальном времени для торговых решений.

- **Операции**:
    - `fetch_order_book`: Получение актуальных данных о стакане заявок из внешнего API.
    - `analyze_order_book`: Анализ заявок для выявления рыночных трендов, ликвидности и спроса.
    - `store_order_book`: Сохранение данных о стакане для последующего анализа.
    - `calculate_spread`: Вычисление разницы между лучшей ценой покупки и продажи.
    - `calculate_depth`: Подсчёт общего объёма ликвидности в стакане.
    - `monitor_order_book`: Отслеживание изменений в стакане заявок в реальном времени.
    - `export_order_book`: Экспорт данных стакана в формат CSV или JSON.
    - `visualize_order_book`: Построение визуализаций (графиков) стакана заявок.
    - `compare_order_books`: Сравнение стаканов для нескольких активов или временных интервалов.

### **MLModel (Модель машинного обучения)**

- **Описание**: Алгоритм, использующий машинное обучение для анализа рыночных данных, прогнозирования цен, объёмов и других метрик. Используется для поддержки принятия решений и автоматизации торговых стратегий.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор модели.
    - `name`: Название модели (например, `PricePredictor`, `VolatilityAnalyzer`).
    - `description`: Краткое описание модели и её функциональности.
    - `algorithm`: Алгоритм, используемый моделью (например, `LSTM`, `Random Forest`, `XGBoost`).
    - `hyperparameters`: Параметры модели (например, количество слоёв, глубина дерева) в формате JSON.
    - `version`: Версия модели (например, `1.0`, `2.1`).
    - `training_dataset_id`: Идентификатор набора данных, использованного для обучения.
    - `performance_metrics`: Метрики оценки качества модели (например, `accuracy`, `mean_squared_error`).
    - `status`: Текущий статус модели (`active`, `training`, `deprecated`).
    - `created_at`: Дата и время создания модели.
    - `updated_at`: Дата последнего обновления модели.

- **Связи**:
    - `MarketData`: Рыночные данные, использованные для обучения модели.
    - `Prediction`: Прогнозы, сгенерированные моделью.
    - `ExternalService`: Источники данных, использованные моделью.
    - `Speculorg.Terminal`: Использование модели для прогнозов и торговых решений.

- **Операции**:
    - `train_model`: Обучение модели на исторических данных с использованием заданного набора гиперпараметров.
    - `predict`: Генерация прогноза на основе текущих или исторических данных.
    - `evaluate_model`: Оценка точности модели на тестовом наборе данных.
    - `update_model`: Обновление модели с учётом новых данных или улучшения алгоритма.
    - `deploy_model`: Развёртывание модели в продакшн для использования в реальном времени.
    - `retire_model`: Снятие модели с использования (например, устаревшие версии).
    - `fetch_model_performance`: Получение метрик производительности модели.
    - `compare_models`: Сравнение нескольких моделей по заданным метрикам (например, точность, скорость прогнозирования).
    - `export_model`: Экспорт модели в формате (например, `ONNX`, `TensorFlow SavedModel`) для интеграции в другие системы.
    - `import_model`: Импорт модели из внешнего источника.
    - `generate_model_report`: Создание отчёта о характеристиках, обучении и производительности модели.

    - `status`: Статус прогноза (`active`, `expired`, `archived`).
    - `evaluation_metrics`: Метрики точности прогноза (например, `mean_absolute_error`, `r_squared`).

- **Связи**:
    - `MLModel`: Модель, создавшая прогноз.

- **Операции**:

    - `analyze_prediction_accuracy`: Анализ точности прогноза с использованием исторических данных.
    - `store_prediction`: Сохранение прогноза для последующего анализа или использования.
    - `validate_prediction`: Проверка корректности и целостности прогноза.
    - `compare_predictions`: Сравнение нескольких прогнозов от разных моделей для выбора наиболее надёжного.
    - `export_prediction`: Экспорт прогноза в формат CSV или JSON для внешнего анализа.
    - `generate_prediction_report`: Создание отчёта на основе прогнозов и их точности.
    - `monitor_prediction`: Отслеживание актуальности прогноза и изменение его статуса при устаревании.
    - `archive_prediction`: Перевод устаревших прогнозов в архив для долгосрочного хранения.

### **Configuration (Конфигурация)**

- **Описание**: Централизованное хранилище и управление настройками системы. Служит для конфигурации модулей, сервисов и приложений, обеспечивая гибкость, безопасность, прозрачность изменений и надёжность работы системы.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор настройки.
    - `key`: Уникальный ключ настройки (например, `max_requests_per_minute`, `api_timeout`, `default_currency`).
    - `value`: Текущее значение настройки (например, число, строка, JSON).
    - `default_value`: Значение по умолчанию, используемое при сбросе настройки.
    - `type`: Тип значения (`string`, `integer`, `boolean`, `json`) для проверки и типизации.
    - `category`: Категория настройки (например, `system`, `security`, `user`, `service`).
    - `is_sensitive`: Флаг, указывающий на необходимость шифрования значения (`true`, `false`).
    - `is_editable`: Флаг, определяющий возможность изменения настройки (`true`, `false`).
    - `description`: Подробное описание назначения настройки.
    - `updated_by`: Идентификатор пользователя или системы, изменившего настройку.
    - `updated_at`: Дата и время последнего изменения настройки.
    - `created_at`: Дата и время создания настройки.

- **Связи**:
    - `ExternalService`: Настройки, относящиеся к внешним сервисам (например, лимиты запросов, ключи API).
    - `SecurityPolicy`: Конфигурации безопасности, такие как длина пароля, время жизни сессии.
    - `User`: Индивидуальные настройки пользователей (например, язык интерфейса).
    - `RiskManagement`: Связь с параметрами управления рисками.
    - `Speculorg.Terminal`: Основной модуль, использующий конфигурацию для настройки системных параметров.

- **Операции**:
    - `create_config`: Создание новой записи конфигурации с валидацией ключевых параметров.
    - `update_config`: Обновление существующей конфигурации с проверкой прав и данных.
    - `fetch_config`: Получение значения настройки по ключу с учётом категории и уровня доступа.
    - `fetch_all_configs`: Получение всех доступных настроек с фильтрацией по категории, типу или уровню доступа.
    - `reset_config`: Сброс настройки к значению по умолчанию.
    - `delete_config`: Удаление устаревших или неиспользуемых настроек.

    - `created_at`: Дата и время создания оповещения.
    - `resolved_at`: Дата и время разрешения или закрытия оповещения (опционально).

    - `timeout`: Таймаут ожидания ответа от эндпоинта (в секундах).

    - `fetch_rate_limits`: Получение списка всех правил ограничений с возможностью фильтрации.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор задачи.
    - `name`: Название задачи (например, `fetch_market_data`, `calculate_risk_metrics`).
    - `status`: Текущий статус задачи (`pending`, `in_progress`, `completed`, `failed`).
    - `priority`: Приоритет задачи (`low`, `medium`, `high`, `critical`).
    - `created_at`: Дата и время создания задачи (тип: `datetime` с UTC).
    - `updated_at`: Дата и время последнего обновления задачи (тип: `datetime` с UTC).
    - `completed_at`: Дата и время завершения задачи (опционально).
    - `retry_count`: Количество попыток повторного выполнения задачи (по умолчанию `0`).
    - `max_retries`: Максимальное количество попыток повторного выполнения.
    - `payload`: Данные, переданные задаче в формате JSON.
    - `result`: Результат выполнения задачи (например, `success`, `error_message`).
    - `worker_id`: Идентификатор воркера, который выполняет задачу.

- **Связи**:
    - `User`: Пользователь, инициировавший задачу (если применимо).
    - `AuditLog`: Логи, связанные с созданием, выполнением и завершением задачи.
    - `ExternalService`: Внешние сервисы, с которыми взаимодействует задача.
    - `Speculorg.Terminal`: Модуль, инициирующий или использующий задачу для выполнения операций.

- **Операции**:
    - `create_task`: Создание новой задачи с заданным именем и данными.
    - `fetch_task_status`: Получение текущего статуса задачи по её идентификатору.
    - `retry_task`: Повторное выполнение задачи при её неудачном завершении.
    - `terminate_task`: Принудительное завершение задачи (например, при тайм-ауте).
    - `list_tasks`: Получение списка всех задач с фильтрацией по статусу, дате или приоритету.
    - `monitor_tasks`: Непрерывный мониторинг задач для выявления зависших или проблемных операций.
    - `audit_task`: Запись операций, связанных с задачей, в лог аудита.
    - `export_task_logs`: Экспорт логов задач для анализа и отладки.
    - `generate_task_report`: Создание отчёта о выполненных задачах за указанный период.

### **Category (Категория)**

- **Описание**: Классификация сущностей по типам, группам или другим признакам, используется для структурирования данных.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор категории.
    - `name`: Название категории (тип: `string`, ограничение длины до 100 символов).
    - `description`: Подробное описание категории (тип: `text`).
    - `parent_id`: Идентификатор родительской категории.
    - `level`: Уровень вложенности категории (тип: `integer`, автогенерация).
    - `slug`: Уникальный текстовый идентификатор для URL и SEO-оптимизации (тип: `string`).
    - `is_active`: Статус активности категории (тип: `boolean`, по умолчанию `true`).
    - `created_at`: Дата и время создания категории (тип: `datetime`, UTC).
    - `updated_at`: Дата и время последнего обновления категории (тип: `datetime`, UTC).

- **Связи**:
    - `Asset`: Связь с сущностью активов (с помощью `uuid`) для классификации финансовых инструментов и данных.
    - `ParentCategory`: Связь с родительской категорией для построения иерархий.
    - `ChildCategories`: Список подкатегорий, связанных с данной категорией.
    - `Speculorg.CMS`: Интеграция для управления категориями через панель администратора.

- **Операции**:
    - `create_category`: Создание новой категории с уникальным идентификатором и базовыми атрибутами.
    - `update_category`: Обновление данных существующей категории, включая описание и статус.
    - `delete_category`: Удаление категории с проверкой на наличие связанных объектов (например, активов).
    - `fetch_hierarchy`: Получение полной иерархической структуры категорий, начиная с заданной.
    - `activate_category`: Активация категории для включения в текущие операции системы.
    - `deactivate_category`: Деактивация категории для временного исключения из активного использования.
    - `sync_with_cms`: Синхронизация категорий с модулем управления контентом Speculorg.CMS.
    - `audit_log`: Запись изменений категории в журнал аудита для отслеживания действий администраторов.

### **Webhook (Вебхук)**

- **Описание**: Механизм для отправки уведомлений о событиях в системе на заданный URL. Используется для интеграции с внешними системами и автоматизации процессов.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор вебхука.
    - `user_id`: Идентификатор пользователя, которому принадлежит вебхук.
    - `event`: Тип события, вызывающего вебхук (например, `order_created`, `trade_executed`, `balance_updated`).
    - `url`: URL-адрес, на который отправляется уведомление.
    - `headers`: Пользовательские заголовки, отправляемые с запросом (например, `Authorization`).
    - `payload_format`: Формат данных, отправляемых в запросе (`JSON`, `XML`).
    - `retry_policy`: Политика повторной отправки в случае ошибки (например, количество повторов, интервалы между ними).
    - `status`: Статус вебхука (`active`, `inactive`).
    - `last_triggered_at`: Дата и время последнего вызова вебхука.
    - `created_at`: Дата и время создания вебхука.
    - `updated_at`: Дата последнего обновления вебхука.

- **Связи**:
    - `User`: Пользователь, настроивший вебхук.
    - `Notification`: Уведомления, связанные с событиями вебхука.
    - `AuditLog`: Логи, фиксирующие вызовы вебхуков.

- **Операции**:
    - `create_webhook`: Создание нового вебхука с заданными параметрами.
    - `update_webhook`: Обновление настроек вебхука (например, изменение URL или события).
    - `delete_webhook`: Удаление вебхука из системы.
    - `trigger_webhook`: Принудительный вызов вебхука для тестирования или отладки.
    - `retry_webhook`: Повторная отправка уведомления при неудаче предыдущей попытки.
    - `fetch_webhooks`: Получение списка всех вебхуков пользователя.
    - `validate_webhook`: Проверка корректности настроек вебхука.
    - `log_webhook_activity`: Запись вызовов вебхуков для аудита и анализа.
    - `disable_webhook`: Деактивация вебхука без его удаления.
    - `export_webhook_settings`: Экспорт настроек вебхука для резервного копирования.

### **WebhookSubscription (Подписка на вебхуки)**

- **Описание**: Настройки подписки пользователя на уведомления о событиях в системе через вебхуки. Позволяет автоматизировать интеграцию с внешними сервисами и системами.

- **Атрибуты**:
    - `uuid`: Уникальный идентификатор подписки.
    - `user_id`: Идентификатор пользователя, оформившего подписку.
    - `event`: Событие, на которое оформлена подписка (например, `order_created`, `trade_executed`, `balance_updated`).
    - `url`: URL, на который отправляются уведомления.
    - `headers`: Дополнительные заголовки, включаемые в запрос (например, `Authorization`).
    - `payload_format`: Формат данных уведомления (`JSON`, `XML`).
    - `status`: Текущий статус подписки (`active`, `inactive`).
    - `retry_policy`: Политика повторной отправки уведомлений (например, количество попыток, интервал между ними).
    - `last_triggered_at`: Дата и время последнего вызова вебхука.
    - `created_at`: Дата и время создания подписки.
    - `updated_at`: Дата последнего изменения настроек подписки.

- **Связи**:
    - `User`: Пользователь, оформивший подписку.
    - `Notification`: Уведомления, связанные с событием подписки.
    - `AuditLog`: Логи, фиксирующие вызовы вебхуков.

- **Операции**:
    - `create_subscription`: Создание новой подписки на вебхуки.
    - `update_subscription`: Обновление параметров подписки (например, изменение URL или события).
    - `delete_subscription`: Удаление подписки из системы.
    - `trigger_webhook`: Принудительная отправка уведомления для проверки или отладки.
    - `retry_webhook`: Повторная отправка уведомления при неудаче предыдущей попытки.
    - `fetch_subscriptions`: Получение списка активных подписок для пользователя.
    - `validate_subscription`: Проверка корректности настроек подписки.
    - `log_subscription_activity`: Логирование вызовов вебхуков для анализа.
    - `disable_subscription`: Временная деактивация подписки без её удаления.
    - `export_subscription_settings`: Экспорт настроек подписки для резервного копирования.
