## Введение

Компоненты в системе Speculorg.Terminal представляют собой независимые единицы, которые выполняют задачи или расширяют функциональность конкретного Контекста или Внешнего сервиса.

За регистрацию и управление жизненным циклом всех Компонентов системы отвечает Speculorg.Terminal.Management.Service.

Все Компоненты интегрированы в единую систему сквозной функциональности через Speculorg.Terminal.Infrastructure.Service.

---

### Принципы

- **Модульно-микросервисная архитектура**: Каждый Компонент функционирует как независимая единица, представленный в одном из следующих форматов:
    - **Микросервис:** Самодостаточная сущность, выполняющая изолированные функции, которую можно масштабировать независимо от других.
    - **Модуль:** Расширение функциональности существующего Микросервиса.
- **Базовые классы**: BaseService, BaseAdapter, BaseModule определяют унифицированные интерфейсы и абстрактные методы для своего типа Компонента, а также внедряют сквозную функциональность.
- **Отказоустойчивость и изоляция ответственности**: Компоненты проектируются так, чтобы решать чётко определённый набор задач и имеют изолированное хранилище данных и состояния, минимизируя влияние их отказа на всю систему.
- **Централизованное управление:** Работа всех Компонентов в системе осуществляется под управлением компонента Speculorg.Terminal.Management.Service.
- **Интеграция с инфраструктурой**: Во все компоненты, через внедрение в базовых классах, интегрирована единая система сквозной функциональности Speculorg.Terminal.Infrastructure.Service.
- **Модульность и расширяемость**: Основной функционал реализуется через базовые Модули и можно подключить дополнительные.

---

### Типы Компонентов

Типы компонентов разделяются на **ContextMicroservice (Микросервис Контекста)**, **ExternalServiceAdapter (Адаптер Внешнего сервиса)** и **Module (Модуль)**.

- **ContextMicroservice (Микросервис Контекста):**
    - **Описание:**
        - Компонент системы, который реализует логику отдельного Контекста системы.
    - **Особенности:**
        - В системе представлен как отдельный микросервис.
        - Реализует шаблон базового класса **BaseService**.
        - Каждый Микросервис обслуживает только один Контекст системы.
        - Расширяет возможности своего Контекста подключением Секций в виде Модулей.
        - Предоставляет API для доступа к своей функциональности, управлению и мониторингу.
        - Использует для взаимодействия REST API, WebSocket и RabbitMQ.
        - Масштабируем и независимо развертывается.
        - Автоматически обнаруживаются через HashiCorp Consul.
        - Speculorg.Terminal.Management.Service управляет жизненным циклом Микросервиса.
        - Speculorg.Terminal.Infrastructure.Service предоставляет Микросервису сквозную функциональность.
    - **Примеры:**
        - `Speculorg.Terminal.Trading.Service`
        - `Speculorg.Terminal.Analytics.Service`
        - `Speculorg.Terminal.Integration.Service`
        - `Speculorg.Terminal.Management.Service`
        - `Speculorg.Terminal.Infrastructure.Service`

- **ExternalServiceAdapter (Адаптер Внешнего сервиса):**
    - **Описание:**
        - Компонент системы, который реализует логику взаимодействия с API конкретного внешнего сервиса.
    - **Особенности:**
        - В системе представлен как отдельный микросервис.
        - Реализует шаблон базового класса **BaseAdapter**.
        - Каждый Адаптер обслуживает только один Внешний сервис.
        - Расширяет возможности своего Внешнего сервиса подключением Секций в виде Модулей.
        - Предоставляет API для доступа к своей функциональности, управлению и мониторингу.
        - Использует для взаимодействия REST API, WebSocket и RabbitMQ.
        - Масштабируем и независимо развертывается.
        - Автоматически обнаруживаются через HashiCorp Consul.
        - Speculorg.Terminal.Management.Service управляет жизненным циклом Адаптера.
        - Speculorg.Terminal.Infrastructure.Service предоставляет Адаптеру сквозную функциональность.
        - Speculorg.Terminal.Integration.Service управляет потоками данных и запросов к Внешнему сервису.
    - **Примеры:**
        - `Speculorg.Terminal.Integration.Exchanges.MEXC.Adapter`
        - `Speculorg.Terminal.Integration.Exchanges.KuCoin.Adapter`
        - `Speculorg.Terminal.Integration.Aggregators.CoinMarketCap.Adapter`
        - `Speculorg.Terminal.Integration.Aggregators.CoinGecko.Adapter`

- **Module (Модуль):**
    - **Описание:**
        - Компонент системы, которые расширяет функциональность другого Компонента.
        - Каждый Модуль проектируется как отдельная Секция:
            - Пример для Микросервиса Контекста: Gateway, UserAdministration, DataExchange, ServiceDiscovery, PortfolioManagement, ExecutionEngine, DataProcessing и т.д.
            - Пример для Адаптера Внешнего сервиса: Spot, Futures, Earn, Sentiment, Global, Metrics и т.д.
    - **Особенности:**
        - В системе представлен как отдельный Компонент - программная библиотека.
        - Реализует шаблон базового класса **BaseModule**.
        - Каждый Модуль обслуживает только один Компонент.
        - Автоматически обнаруживаются через HashiCorp Consul.
        - Speculorg.Terminal.Management.Service управляет жизненным циклом Модуля.
        - Speculorg.Terminal.Infrastructure.Service предоставляет Модулю сквозную функциональность.
    - **Примеры:**
        - `Speculorg.Terminal.Trading.OrderManagement.Module`
        - `Speculorg.Terminal.Market.DataCollection.Module`
        - `Speculorg.Terminal.Analytics.TechnicalAnalysis.Module`
        - `Speculorg.Terminal.Assets.PortfolioManagement.Module`
        - `Speculorg.Terminal.Assets.AssetManagement.Module`
        - `Speculorg.Terminal.Integration.Wallets.Module`
        - `Speculorg.Terminal.Integration.AdapterManagement.Module`
        - `Speculorg.Terminal.Integration.DataManagement.Module`
        - `Speculorg.Terminal.Integration.Exchanges.MEXC.Spot.Module`
        - `Speculorg.Terminal.Integration.Exchanges.MEXC.Futures.Module`
        - `Speculorg.Terminal.Integration.Aggregators.CoinMarketCap.Metrics.Module`
        - `Speculorg.Terminal.Integration.Exchanges.KuCoin.Spot.Module`
        - `Speculorg.Terminal.Integration.Exchanges.KuCoin.Futures.Module`
        - `Speculorg.Terminal.Integration.Exchanges.KuCoin.Earn.Module`
        - `Speculorg.Terminal.Security.EncryptionManagement.Module`
        - `Speculorg.Terminal.Management.UserManagement.Module`
        - `Speculorg.Terminal.Infrastructure.Traefik.Module`
        - `Speculorg.Terminal.Infrastructure.Keycloak.Module`
        - `Speculorg.Terminal.Infrastructure.RabbitMQ.Module`
        - `Speculorg.Terminal.Infrastructure.Prometheus.Module`
        - `Speculorg.Terminal.Infrastructure.Grafana.Module`
        - `Speculorg.Terminal.Infrastructure.Sentry.Module`
        - `Speculorg.Terminal.Infrastructure.HashiCorpVault.Module`

### Базовый класс **BaseService**

Все компоненты типа **ContextMicroservice** наследуются от базового класса **BaseService**, который задаёт единый абстрактный интерфейс для внедрения общих бизнес-правил и сквозной функциональности.

- **Имя:** Speculorg.Terminal.Core.BaseService

- **Описание:**
    - Абстрактный базовый класс для создания микросервисов компонентов. Он не зависит от конкретной реализации и задаёт стандартный набор методов для управления жизненным циклом, обработки запросов, логирования, мониторинга и фоновых задач.

- **Основные методы:**
    - `initialize()`: Инициализация микросервиса, настройка окружения, зависимостей и конфигураций (например, подключение к Consul, Vault, Keycloak).
    - `start()`: Запуск микросервиса и его регистрация в системе.
    - `pause()`: Приостановка обработки входящих запросов и фоновых задач.
    - `restart()`: Перезапуск микросервиса с сохранением текущего состояния.
    - `stop()`: Корректная остановка микросервиса с освобождением всех ресурсов.
    - `handle_request(request: dict) -> dict`: Унифицированная обработка входящих запросов.
    - `process_task(task: dict) -> None`: Обработка фоновых задач.
    - `process_event(event: dict) -> None`: Обработка входящих событий.
    - `log_event(event: dict)`: Единое логирование событий микросервиса для аудита и диагностики.
    - `monitor_metrics()`: Мониторинг состояния и отправка метрик производительности в Prometheus.

- **Особенности:**
    - Единый интерфейс для управления жизненным циклом микросервиса (инициализация, запуск, пауза, рестарт, остановка).
    - Расширение функциональности через подключаемые Модули.
    - Скрытие инфраструктурных деталей (работа с Consul, Vault, Keycloak, Sentry, Prometheus, ELK Stack).
    - Унифицированная обработка ошибок, логирование и мониторинг.
    - Поддержка аутентификации/авторизации (RBAC) и безопасного хранения секретов.
    - Интеграция с системами очередей (RabbitMQ, Celery) для фоновых задач и событийного взаимодействия.

### Базовый класс **BaseAdapter**

Все компоненты типа **ExternalServiceAdapter** наследуются от базового класса **BaseAdapter**, который задаёт единый абстрактный интерфейс для внедрения общих бизнес-правил и сквозной функциональности.

- **Имя:** Speculorg.Terminal.Core.BaseAdapter

- **Описание:**
    - Абстрактный базовый класс для реализации адаптеров интеграции. Он включает единый интерфейс управления жизненным циклом, обработки запросов, логирования и мониторинга, а также добавляет специфичные для работы с внешними сервисами методы.

- **Основные методы:**
    - `initialize()`: Инициализация адаптера, настройка окружения и зависимостей (подключение к Consul, Vault и т.п.).
    - `start()`: Запуск адаптера и регистрация в системе.
    - `pause()`: Приостановка работы адаптера.
    - `restart()`: Перезапуск адаптера.
    - `stop()`: Корректная остановка адаптера с освобождением ресурсов.
    - `connect()`: Установление соединения с внешним сервисом.
    - `fetch_data()`: Получение данных от внешнего сервиса.
    - `send_data()`: Отправка данных во внешний сервис.
    - `handle_request(request: dict) -> dict`: Обработка входящих запросов.
    - `process_task(task: dict) -> None`: Обработка фоновых задач.
    - `process_event(event: dict) -> None`: Обработка входящих событий.
    - `log_event(event: dict)`: Единое логирование событий адаптера.
    - `monitor_metrics()`: Мониторинг состояния адаптера и отправка метрик в Prometheus.

- **Особенности:**
    - Единый интерфейс управления жизненным циклом адаптера (инициализация, запуск, пауза, рестарт, остановка).
    - Расширение функциональности с помощью Модулей.
    - Расширение функциональности за счёт дополнительных методов для работы с внешними API (connect, fetch_data, send_data).
    - Изоляция логики работы с конкретным внешним сервисом и скрытие деталей реализации.
    - Асинхронная обработка запросов и интеграция с системами очередей (RabbitMQ, Celery).
    - Интеграция с HashiCorp Consul, Vault и системами мониторинга (Prometheus, Sentry, ELK Stack).

## Список Микросервисов

### Speculorg.Terminal.API.Service

- **Описание:**
    - Компонент `Speculorg.Terminal.API.Service` отвечает за маршрутизацию входящих запросов к соответствующим микросервисам системы Speculorg.Terminal. Этот сервис является единой точкой входа для всех внешних API-запросов, обеспечивая безопасность и управление трафиком.

- **Тип компонента:**
    - Микросервис, API Gateway

- **Функции:**
    - Маршрутизация запросов: Направляет входящие HTTP-запросы к соответствующим микросервисам на основе URL и HTTP-методов.
    - Балансировка нагрузки: Распределяет трафик между несколькими экземплярами микросервисов для обеспечения высокой доступности и производительности.
    - Аутентификация и авторизация: Интеграция с сервисом безопасности для проверки подлинности пользователей и их прав доступа.
    - Rate Limiting: Ограничение количества запросов от одного пользователя или IP-адреса для предотвращения перегрузок и атак.
    - Мониторинг и логирование: Сбор метрик и логов для анализа производительности и выявления потенциальных проблем.
    - Обратное проксирование: Перенаправление запросов к внутренним сервисам, скрывая их от прямого доступа извне.

- **Интерфейсы и API:**
    - REST API: Предоставляет стандартные HTTP-интерфейсы для взаимодействия с внешними клиентами.
        - GET /api/v1/health: Проверка состояния API Gateway.
        - POST /api/v1/auth/login: Аутентификация пользователя и выдача токена.
        - Другие эндпоинты: Маршрутизация запросов к соответствующим микросервисам, например, `/api/v1/trading/orders`, `/api/v1/market/tickers/{symbol}` и т.д.
    - WebSocket API: Поддержка двунаправленной связи для передачи данных в реальном времени.
        - WS /ws/notifications: Подключение для получения уведомлений и обновлений в реальном времени.

- **Зависимости:**
    - `HashiCorp Consul`: Для обнаружения сервисов и получения конфигураций.
    - `Speculorg.Terminal.Security.Service`: Для аутентификации и авторизации запросов.
    - `Prometheus` и `Grafana`: Для сбора и визуализации метрик.

- **Интеграции:**
    - `HashiCorp Consul`: для автоматического обнаружения доступных микросервисов и их обновления в реальном времени.
    - `Speculorg.Terminal.Security.Service`: Проверка токенов и прав доступа перед маршрутизацией запросов.
    - `ELK Stack`: Для сбора и анализа логов.
    - `Prometheus` и `Grafana`: Для анализа и визуализации метрик и логов.

- **Конфигурации:**
    - Настройки маршрутизации: Определение правил маршрутизации для различных микросервисов.
    - Rate Limiting параметры: Настройка лимитов запросов для защиты от перегрузок.
    - SSL/TLS сертификаты: Конфигурация для обеспечения защищённых соединений.
    - Параметры интеграции с `HashiCorp Consul`: Адреса и порты `HashiCorp Consul` сервера для обнаружения сервисов.
    - Параметры аутентификации: Настройки для взаимодействия с `Speculorg.Terminal.Security.Service` и `Keycloak`.

- **Контексты участия:**
    - `Speculorg.Terminal.Trading`: Маршрутизация запросов для управления торговыми операциями.
    - `Speculorg.Terminal.Market`: Обеспечение доступа к рыночным данным и котировкам.
    - `Speculorg.Terminal.Assets`: Управление портфелями и активами пользователей.
    - `Speculorg.Terminal.Analytics`: Доступ к аналитическим данным и прогнозам.
    - `Speculorg.Terminal.RiskManagement`: Управление рисками и защитными механизмами.
    - `Speculorg.Terminal.Notifications`: Обеспечение доставки уведомлений пользователям.

- **Технологии:**
    - `FastAPI`: Фреймворк для реализации микросервиса.
    - `Traefik`: Используется как API Gateway для маршрутизации и балансировки нагрузки.
    - `Python`: Основной язык программирования для написания конфигураций и скриптов.
    - `HashiCorp Consul`: Для обнаружения сервисов и получения конфигураций.
    - `Docker`: Контейнеризация API Gateway для упрощения развертывания и масштабирования.

    - Управление портфелями: Создание и удаление портфелей пользователей, обновление на основе выполненных ордеров, управление ребалансировкой и распределением активов.

    - Генерация отчетов: Создание подробных отчетов о состоянии портфелей и исторических изменениях для пользователей и администраторов.

        - GET /assets/analytics/{portfolio_id}: Получение аналитических данных по портфелю.
        - GET /assets/categories: Получение списка категорий активов.
        - POST /assets/favorites: Добавление актива в избранное.

### Elasticsearch

- **Описание:**
    - `Elasticsearch` — это распределенная поисковая и аналитическая система на основе Lucene. Она обеспечивает высокопроизводительный поиск, агрегацию и анализ больших объемов данных в реальном времени.

- **Тип компонента:**
    - Поисковая и аналитическая система

- **Функции:**
    - Индексация и хранение больших объемов структурированных и неструктурированных данных
    - Высокопроизводительный полнотекстовый поиск и фильтрация
    - Поддержка сложных запросов и агрегаций для анализа данных
    - Масштабируемость и распределенность через кластеризацию
    - Интеграция с `Kibana` для визуализации данных

- **Интеграции:**
    - `Logstash`: Для получения и индексирования логов и других данных
    - `Speculorg.Terminal.Infrastructure.Service`: Для хранения и анализа логов всех микросервисов и инфраструктурных компонентов
    - `Grafana`: В качестве источника данных для визуализации

### Kibana

- **Описание:**
    - `Kibana` — это инструмент для визуализации данных, хранящихся в `Elasticsearch`. Он предоставляет мощные средства для создания интерактивных дашбордов, проведения анализа данных и отображения логов.

- **Тип компонента:**  
    - Инструмент визуализации данных

- **Функции:**
    - Создание настраиваемых дашбордов с визуализациями данных из `Elasticsearch`
    - Поддержка фильтрации и поиска по данным
    - Интерактивные графики, диаграммы и карты для анализа данных
    - Настройка оповещений на основе данных и событий
    - Интеграция с `Kibana Lens` для упрощенного создания визуализаций

- **Интеграции:**
    - `Elasticsearch`: В качестве основного источника данных для визуализаций и анализа
    - `Speculorg.Terminal.Infrastructure.Service`: Для отображения логов и метрик инфраструктуры
    - `Grafana`: В качестве дополнительного инструмента для визуализации данных
