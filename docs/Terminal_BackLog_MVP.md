
# Журнал задач Speculorg.Terminal (MVP)

Ниже представлен список текущих задач (бэклог) для реализации MVP:

---

## Легенда

- **Приоритет**:
    - **P0** (выполнено): задача выполнена.
    - **P1** (высокий): необходимо выполнить в первую очередь.
    - **P2** (средний): желательно выполнить в рамках текущей итерации.
    - **P3** (низкий): выполнение возможно при наличии времени или перенос на следующую итерацию.
- **Статус**:
    - **Backlog**: задача сформирована, ждёт начала.
    - **In Progress**: задача в работе.
    - **Review**: задача завершена, ожидает проверки.
    - **Done**: задача полностью завершена и принята.

---

## 1. Инфраструктура

- **[TERM-1] Подготовка окружения для Terminal**
    - **Описание**: Настроить окружение Docker Compose, разработать ядро и базовый класс ContextMicroservice, поднять основные инфраструктурные микросервисы - Consul, Vault, Traefik.
    - **Приоритет**: P1
    - **Статус**: In Progress

- **[TERM-2] Настройка Keycloak**
    - **Описание**: Внедрить аутентификацию/авторизацию (OpenID Connect/OAuth2) через Keycloak. Настроить базовые роли (User, Admin), систему токенов и refresh-токенов.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-3] Настройка RabbitMQ**
    - **Описание**: Настроить обмен сообщениями между микросервисами Terminal с использованием очередей RabbitMQ; определить основные топики и маршруты.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-4] Настройка PostgreSQL и TimescaleDB**
    - **Описание**: Инициализировать базы данных, создать структуры для хранения основных данных.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-5] Настройка CI/CD**
    - **Описание**: Создать пайплайн сборки и тестирования сервиса (Docker Images, Unit Tests) с использованием GitHub Actions. Настроить автоматический деплой на dev-окружение.
    - **Приоритет**: P3
    - **Статус**: Backlog

---

## 2. Базовая функциональность

- **[TERM-6] Управление пользователями и правами**
    - **Описание**: Реализовать CRUD для профилей пользователей, связанных с Keycloak, включая сохранение индивидуальных настроек и прав доступа.
    - **Приоритет**: P1
    - **Статус**: Backlog

- **[TERM-7] Управление конфигурацией**
    - **Описание**: Создать таблицу или сервис для хранения глобальных настроек (API-ключи, лимиты, интервал обновлений), доступный через админ-панель.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-8] Управление активами и категориями**
    - **Описание**: Реализовать CRUD для библиотеки активов, их категорий и атрибутов (крипто, акции, облигации и т.п.).
    - **Приоритет**: P1
    - **Статус**: Backlog

- **[TERM-9] Управление избранными активами**
    - **Описание**: Позволить пользователю формировать список избранных инструментов для быстрого доступа и мониторинга.
    - **Приоритет**: P2
    - **Статус**: Backlog

---

## 3. Интеграции

- **[TERM-10] Интеграция с CoinMarketCap (агрегатор)**
    - **Описание**: Разработать базовый класс ExternalServiceAdapter, подключить API CoinMarketCap для получения информации об активах и глобальных рыночных метрик. Обеспечить периодическое обновление и кэширование данных.
    - **Приоритет**: P1
    - **Статус**: Backlog

- **[TERM-11] Интеграция MEXC (спот-рынок)**
    - **Описание**: Реализовать сбор рыночных данных (тикеры, стаканы, лента сделок) и торговой информации (баланс, ордера, сделки) с биржи MEXC.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-12] Интеграция Kucoin (спот-рынок)**
    - **Описание**: Аналогичная интеграция, как с MEXC, но применительно к Kucoin. Собрать рыночные и торговые данные.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-13] Общий модуль хранения исторических данных**
    - **Описание**: Разработать механизм постоянного сбора и сохранения OHLCV и ленты сделок (TimescaleDB). Обеспечить ручную и автоматическую загрузку.
    - **Приоритет**: P1
    - **Статус**: Backlog

---

## 4. Торговая функциональность

- **[TERM-14] Лимитные и рыночные заявки (Spot Trading)**
    - **Описание**: Реализовать эндпоинты (REST/WS) для выставления, отмены, статуса лимитных и рыночных ордеров на спот-рынках MEXC и Kucoin.
    - **Приоритет**: P1
    - **Статус**: Backlog

- **[TERM-15] Управление торговыми параметрами**
    - **Описание**: Позволить пользователям настраивать параметры для сделок (авто-риджайнинг ордеров, плечо — если доступно, ограничения риска).
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-16] Отслеживание баланса и открытых ордеров**
    - **Описание**: Создать панель/модуль, отображающий актуальный баланс, активные ордера, историю сделок по выбранной бирже.
    - **Приоритет**: P2
    - **Статус**: Backlog

---

## 5. UI/UX

- **[TERM-17] Базовые пользовательские страницы Terminal**
    - **Описание**: Реализовать стандартный набор страниц (список активов, страница каждого актива, торговый интерфейс, профиль пользователя).
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-18] Админ-интерфейс для операций**
    - **Описание**: Создать административную панель для управления глобальными настройками, правами пользователей, мониторингом подключений к биржам.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-19] Визуализация рыночных данных (Charts)**
    - **Описание**: Подключить библиотеки для графиков (Candlestick, объёмы, индикаторы) и отобразить исторические данные (OHLCV).
    - **Приоритет**: P3
    - **Статус**: Backlog

---

## 6. Безопасность

- **[TERM-20] Шифрование и хранение API-ключей**
    - **Описание**: Использовать Vault для безопасного хранения ключей доступа к биржам. Гарантировать шифрование при хранении и передаче ключей.
    - **Приоритет**: P1
    - **Статус**: Backlog

- **[TERM-21] RBAC-конфигурация**
    - **Описание**: Разделить уровни доступа (например, Trader, Viewer, Admin) и проверить корректность ограничений в Terminal (доступ к ордерам, настройкам).
    - **Приоритет**: P2
    - **Статус**: Backlog

---

## 7. Тестирование и мониторинг

- **[TERM-22] Покрытие тестами ключевых функций**
    - **Описание**: Написать юнит-тесты для API интеграций (MEXC, Kucoin), CoinMarketCap, а также интеграционные тесты для торговых операций и хранения данных.
    - **Приоритет**: P1
    - **Статус**: Backlog

- **[TERM-23] Настройка Sentry и ELK**
    - **Описание**: Включить Sentry для сбора ошибок, настроить централизованное логирование в ELK (Elastic + Logstash + Kibana). Обеспечить просмотр логов для мониторинга.
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-24] Интеграция Prometheus и Grafana**
    - **Описание**: Собрать метрики производительности (задержки API, время обработки ордеров, активность очередей RabbitMQ), визуализировать в Grafana.
    - **Приоритет**: P3
    - **Статус**: Backlog

---

## 8. DevOps и процесс развёртывания

- **[TERM-25] Автоматизация деплоя (Ansible, Terraform)**
    - **Описание**: Разработать плейбуки Ansible для подготовки серверов и конфигурации, использовать Terraform для инициализации инфраструктуры (при необходимости).
    - **Приоритет**: P2
    - **Статус**: Backlog

- **[TERM-26] Настройка Pre-commit и линтеров**
    - **Описание**: Добавить проверку кода (Flake8, Black или аналог), линтеров YAML/JSON (при использовании Ansible, Terraform), чтобы поддерживать единый кодстайл.
    - **Приоритет**: P3
    - **Статус**: Backlog

---

## Дополнительно

- Все задачи соответствуют **Phase 1 (MVP)** разработки Speculorg.Terminal.
- Перед началом работы над любой задачей возможна декомпозиция на подзадачи, если объём велик.
- Задачи будут **уточняться, изменяться и дополняться** по мере эволюции приоритетов, требований и обратной связи.
