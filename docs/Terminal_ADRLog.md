## ADR-007: Утверждение плана проекта и бэклога для Specul.Terminal (MVP)

- **Дата:** 2024.10.12

- **Контекст:**
    - Завершили подготовительную работу по проекту Specul.Terminal, включая разработку детального плана проекта и составление бэклога задач для MVP.
Это включает определение ключевых компонентов, функциональности и приоритетов для эффективного выполнения проекта.

- **Решение:**
    - Утвердить предложенный план проекта Specul.Terminal (MVP) и бэклог, чтобы приступить к фазе реализации согласно установленным приоритетам и срокам.

- **Последствия:**
    - Команды разработки и инфраструктуры могут начать работу над задачами из бэклога.
    - Обеспечена ясность в отношении приоритетов и последовательности выполнения задач.
    - Закладывается прочный фундамент для последующего развития и масштабирования системы.

- **Статус:** Принято

## ADR-006: Переименование и улучшение структуры компонентов сторонних сервисов

- **Дата:** 2024.10.10

- **Контекст:**
    - Переименование `ExternalServices` в `ThirdPartyComponents` для точности понимания и удобства навигации.
    - Упрощение и оптимизация именования, чтобы четко отразить роль каждого стороннего компонента и его интеграцию с системой Specul.Terminal.

- **Решение:**
    - Изменены все упоминания `ExternalServices` на `ThirdPartyComponents`.
    - Пересмотрена иерархия сторонних сервисов и их секций для удобства навигации и лучшего понимания.
    - Все ключевые компоненты учтены и интегрированы в новую структуру с учетом их ролей.

- **Последствия:**
    - Логика именования и структуры стала более понятной и точной.
    - Улучшена навигация по элементам, интеграция компонентов упростилась.
    - Новая структура поддерживает дальнейшее развитие и расширение системы с четким отражением ролей компонентов.

- **Статус:** Принято

## ADR-005: Определение стратегий и инфраструктуры для маркетмейкинга, арбитража и HFT

- **Дата:** 2024.10.10

- **Контекст:**
    - Реализация и интеграция компонентов для управления стратегиями маркетмейкинга, арбитража и высокочастотной торговли (HFT) в системе Specul.Terminal.

- **Решение:**
    - Включены контексты:
        - `Specul.Terminal.Trading.MarketMaking`: управление ордербуком, регулирование спредов, анализ глубины рынка.
        - `Specul.Terminal.Trading.AlgorithmicTrading`: алгоритмические стратегии, их оптимизация и бэктестинг.
        - `Specul.Terminal.Trading.Arbitrage`: реализация арбитражных стратегий между биржами и торговыми парами.
    - Настроены инфраструктурные компоненты:
        - `Specul.Terminal.Infrastructure.ExternalServices.RedisCache` для кэширования рыночных данных.
        - `Specul.Terminal.Infrastructure.ExternalServices.Prometheus` и `Grafana` для мониторинга и визуализации производительности.
        - `Specul.Terminal.Infrastructure.ExternalServices.Sentry` для обработки ошибок и уведомлений.

- **Последствия:**
    - Реализована структура для поддержки маркетмейкинга и арбитража.
    - Повышена производительность и масштабируемость за счет кэширования данных и асинхронной обработки задач.
    - Обеспечена поддержка анализа и мониторинга работы стратегий в реальном времени.

- **Статус:** Принято

## ADR-004: Внедрение сторонних компонентов

- **Дата:** 2024.10.02

- **Контекст:**
    - Интеграция ключевых сторонних компонентов для обеспечения функциональности, надежности и масштабируемости системы Specul.Terminal.

- **Решение:**
    - Использовать Traefik как основной балансировщик нагрузки и маршрутизатор запросов.
    - Внедрить Keycloak для управления пользователями и обеспечения SSO.
    - Настроить Consul для обнаружения сервисов и управления конфигурациями.
    - Внедрить Vault для безопасного хранения секретов и ключей доступа.
    - Использовать RabbitMQ для обмена сообщениями между микросервисами.
    - Настроить Celery для выполнения асинхронных задач и фоновых процессов.
    - Использовать PostgreSQL для реляционного хранения данных и TimescaleDB для временных рядов.
    - Интегрировать Redis для высокопроизводительного кэширования данных.
    - Настроить Sentry для отслеживания и уведомлений о критических ошибках.
    - Настроить Prometheus для сбора метрик и Grafana для визуализации.
    - Интегрировать ELK Stack для сбора, хранения и анализа логов.

- **Последствия:**
    - Обеспечена надежная маршрутизация и балансировка нагрузки с Traefik.
    - Улучшена безопасность и управление доступом с Keycloak и Vault.
    - Повышена устойчивость и масштабируемость системы через Consul и RabbitMQ.
    - Обеспечена высокая производительность через Redis и Celery.
    - Улучшен мониторинг и логирование через Prometheus, Grafana и ELK Stack.
    - Повышена надежность системы через Sentry для отслеживания ошибок.

- **Статус:** В работе

    - Снижены риски недопонимания и ошибок из-за различий в терминологии.
