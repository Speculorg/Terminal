
# Журнал архитектурных решений Specul.Terminal

---

## [2025.09.15] ADR-011: Внедрение KV
- KV (Key:Value storage) - единый источник правды (SoT) для несекретных, разделяемых и идемпотентных состояний.
- Добавлен агрегат `KV`, адаптер `ConsulKVClient`, фасады `marker`/`status`/`cert`/`config`.
- Все операции чтения/записи только через фасады (исключить прямые HTTP вызовы).
- Зарезервировано архитектурное место под автоматическую ротацию сертификатов (Consul + Vault), но сама ротация остаётся задачей в плане.
- Добавлен технический документ `docs\Terminal_Idempotency_SoT.md` 


## [2025.09.04] ADR-010: Логирование и конфигурация
- Введён пакет core.logging с JSON-логированием в stdout/stderr.
- Разделение конфигурации на слои:
  - settings.env - только настраиваемые параметры окружения, реально влияющие на перенос и поведение.
  - docker-compose.yml - декларация сервисов и развёртывательные константы, «склейка» ${…} из settings.env.
  - source/core/settings/settings.py - чтение/валидация/нормализация, производные значения (SAN и др.), публикация SETTINGS и CONFIG_HASH.
  - код читает параметры только через SETTINGS; доступ к сырому окружению не допускается (запрещены os.environ, os.getenv); "паспорт" экземпляра сервиса находятся в SETTINGS.context.
  - сервисные конфиги (consul_*.hcl, vault_*.hcl, traefik.yml) - локальная логика конкретного сервиса, могут требовать обязательные ключи окружения.
- PKI в Vault параметризована путями монтирования: VAULT_PKI_ROOT_PATH и VAULT_PKI_INT_PATH. Бутстрап Vault всегда по HTTP, далее - mTLS. Листовые сертификаты теперь пишутся как fullchain (leaf + chain) в *.crt; корень - ca.crt. Это устранило ошибки x509: certificate signed by unknown authority.


## [2025.08.24] ADR-009: Уточнение базовых каркасов и деление ядра
- Каркас сервиса BaseService упразднён как дублирующий. Теперь используются базовые каркасы ContextMicroservice (service.py), ExternalServiceAdapter (adapter.py) и Module (module.py).
- Переносён и упрощён `.\settings.py`; унификация ENV и путей.
- Единый healthcheck-скрипт /core/runtime/health_check.py и формат здоровья.
- Docker Compose: общие healthchecks, `SERVICE_HEALTH_FILE=/run/terminal/health/<svc>.json`.
- Структура core/* (runtime/infra/observability/net/settings).


## [2025.07.21] ADR-008: Внедрение mTLS для внутренних сервисов
- Для защиты взаимодействия Vault, Consul и Traefik внедрён mTLS.
- Использован внутренний PKI Vault для генерации и управления сертификатами.
- Установлены настройки TLS v1.2+.
- Обеспечена автоматическая генерация и распространение сертификатов.


## [2025.07.06] ADR-007: Vault - переход на Consul Storage Backend
- Vault переведён на использование Consul как backend-хранилища.
- ACL-политики Vault адаптированы к Consul.


## [2025.06.04] ADR-006: Consul - политики и токены ACL 
- Автоматизированы создание и выдача токенов Consul для сервисов.
- Используется унифицированная структура ACL-политик.
- Токены и политики создаются и применяются автоматически при инициализации.


## [2024.12.19] ADR-005: Централизация управления жизненным циклом сервисов (BaseService)
- Добавлен и внедрён базовый сервис: BaseService
- Введена обработка сигналов, корректное завершение subprocess и graceful shutdown.


## [2024.10.12] ADR-004: Утверждение плана проекта и бэклога для Specul.Terminal (MVP)
- Завершено определение функциональности и ключевых компонентов
- Разработаны дорожная карта MVP и бэклог задач.


## [2024.10.02] ADR-003: Использование сторонних компонентов
- Решено использовать сторонние компоненты для обеспечения ключевой функциональности, надежности и масштабируемости в системе Specul.Terminal:
    - Consul для обнаружения сервисов и управления конфигурациями.
    - Vault для безопасного хранения секретов и ключей доступа.
    - Traefik как основной балансировщик нагрузки и маршрутизатор запросов.
    - Keycloak для управления пользователями и обеспечения SSO.
    - RabbitMQ для обмена сообщениями между микросервисами.
    - Celery для выполнения асинхронных задач и фоновых процессов.
    - PostgreSQL для реляционного хранения данных и TimescaleDB для временных рядов.
    - Redis для высокопроизводительного кэширования данных.
    - Sentry для отслеживания и уведомлений о критических ошибках.
    - Prometheus для сбора метрик и Grafana для визуализации.
    - ELK Stack для сбора, хранения и анализа логов.


## [2024.09.15] ADR-002: Согласование терминологии и стандартов именования
- Решено обеспечить единообразие терминологии в документации и коде:
